# 使用指南

本指南介绍当前版本可操作的流程。先阅读 [当前状态](status.md)：只有指定国服种火作业完成了五项实机验收，其他作业、副本和安装版不能据此视为稳定。

## 1. 选择启动方式

### 安装版

安装版目前只用于验收测试，**安装、首启和完整实机流程尚未验收**。

1. 获取并运行发布者提供的 Windows NSIS 安装包。
2. 安装 64 位 Python 3.12，并按实际安装目录安装固定依赖：

   ```powershell
   py -3.12 -m pip install -r "<HugoFgo 安装目录>\cv\requirements.txt"
   ```

   也可用 `HUGOFGO_PYTHON` 指向已安装这些依赖的解释器。
3. 准备 adb 和安卓模拟器，可用 `HUGOFGO_ADB` 指定 `adb.exe`。
4. 启动 HugoFgo，在“设置与资源”选择区服并下载图库。

安装包随带 Node.js 和资源脚本，资源更新不需要另装 Node.js；**不随包附带 Python 或图库**。作业、图库、设置和运行证据位于 `%APPDATA%/com.hugofgo.desktop/` 下的 `jobs/`、`data/`、`run-settings.json` 和 `logs/`。

### 源码开发版

按 [开发指南](development.md#1-环境准备) 安装 Node.js、Rust、Python 和回放依赖，然后：

```bash
npm install
npm run resources:update
npm run tauri dev
```

开发期的作业、资源和运行证据使用项目下的 `jobs/`、`data/` 和 `logs/`。

### 浏览器预览

`npm run dev` 只用于界面预览和作业查看。设备命令、真实运行、桌面作业库、运行历史和资源任务不可用；不要把它当成桌面版故障。

## 2. 准备图库

资源来自 Atlas Academy，需要联网。桌面版打开“设置与资源”，选择区服后执行：

- **检查更新**：查看远端版本。
- **增量更新**：下载新增、变更或损坏的文件，日常使用优先选择。
- **校验**：按 SHA-256 检查本地文件。
- **完整校准**：低频同步旧元数据。

CN、JP、TW 的图库和清单分别保存在 `data/<区服>/`，但**执行器当前只支持 CN**。开发版也可使用：

```bash
npm run resources:check
npm run resources:update
npm run resources:verify
```

空库会显示占位卡；首次更新完成后编队界面会重新加载。字段和目录说明见 [资源、素材与引用](resources.md)。

## 3. 运行已验收的种火作业

以下是目前证据最完整的操作路径，使用 `jobs/娄希、娄希、奥伯龙.json`。

开始前确认：

- 国服，模拟器为精确 16:9 横屏且不低于 1280×720；本次验收使用 1280×720。
- adb 能发现设备，游戏账号、编队和概念礼装符合作业。
- 助战列表已预先筛选到所需职阶；执行器不会自动切换职阶页签。
- AP 足够，或明确配置允许的恢复道具。默认仅允许青铜果实；圣晶石虽可在设置中显式勾选，但其恢复确认路径当前仍会安全停止，不能视为已可用。
- 从助战选择页启动；其他起点的接续限制见 [当前状态](status.md#3-当前执行边界)。

操作：

1. 在作业库打开该作业，检查编队、三面动作、技能目标和宝具卡序。
2. 在“设置与资源”检测并选择 adb 设备。
3. 设置连续出击场数和 AP 恢复白名单；只复现验收时保持仅青铜果实。
4. 保存作业，在编队页点击“开始”。
5. 运行面板确认真实画面、面/回合、动作、完成场数和恢复消耗。

需要结束时点击“停止”。执行器在当前动作边界停止；桌面壳最多等待终端事件 30 秒，超时才终止执行器进程树。不要在停止后假定所有输入都已瞬时中止，先观察面板终端状态。

## 4. 编队和导入其他作业

1. 在编队页选择六个槽位的从者、概念礼装和御主礼装。
2. 标记助战位，并按需要指定助战从者、概念礼装或冠位条件。
3. 打开战斗编排，按面和回合添加技能、御主技能、换人、目标切换与攻击。
4. 配置宝具卡序、固定卡序或补刀策略。
5. 保存到作业库，或导出 JSON 备份。

作业面板也支持粘贴 Chaldea 分享链接或 Team ID，以及导入本地 JSON。Chaldea 导入需要联网；导入后必须检查编队、技能目标、宝具卡序和选卡策略。

`examples/sample-job.json` 用于说明文件结构，可能包含当前执行器不支持的二次选择，**不是首个可运行作业示例**。字段与执行限制见 [作业格式](job-format.md)。

## 5. 设备预览与测试点击

桌面版中：

1. 启动安卓模拟器并启用 adb 连接。
2. 在设备面板点击“检测设备”，选择状态为 `device` 的设备。
3. 读取分辨率和 DPI，再截取画面确认识别对象。
4. 如需测试坐标，使用测试点击功能。

测试点击会向模拟器发送真实输入，点击预览截图也会触发测试。不要在未知画面或涉及道具消费的页面试点。其他分辨率会被拒绝，不进行盲目缩放点击。

## 6. 理解运行结果与安全停止

- **完成**：达到固定场数，或清 AP 阶段到达 AP 恢复页且未使用道具。
- **手动停止**：用户请求在动作边界生效，属于主动结束。
- **失败或安全停止**：程序无法确认画面、动作、卡面或恢复条件时主动停止，不应通过连续人工点击替它“闯过去”。

常见保护行为：

- 空白名单遇到 AP 不足时停止，不选择圣晶石或其他果实。
- 恢复确认框与待确认白名单道具不一致时停止。
- 身份、卡色、宝具归属或进度持续无法确认时停止。
- 未知页面和未支持的弹窗不会盲目点击。
- 战斗中途接续的当前面只补刀，下一面才恢复作业动作。

## 7. 查看运行记录与证据

在“运行记录”中查看作业、设备、区服、起止时间、耗时、完成场数、结果和恢复消耗。点击“定位日志与失败截图”可查看证据路径。

每次运行的完整证据位于 `logs/farm/<运行ID>/`：

- `events.jsonl`：动作、状态、警告和终端事件。
- `result.json`：最终状态、原因、进度与消耗。
- `observation.json`：最后一帧感知结果。
- `failure.png`：非完成运行的最终画面（可用时）。

全局索引是 `logs/run-history.jsonl`。安装版的这些文件位于应用数据目录，开发版位于项目目录。反馈故障时保留整个运行目录，不要只截取一句错误。

## 8. 故障排查

| 现象 | 处理方式 |
| --- | --- |
| 从者或礼装图片缺失 | 在资源中心增量更新，再执行校验；开发版也可用 `resources:update` / `resources:verify` |
| 资源更新失败 | 检查 Atlas Academy 与 GitHub 网络，保留任务输出后重试 |
| 作业保存、设备或资源按钮不可用 | 确认使用桌面版，而不是浏览器预览 |
| 没有发现设备 | 启动模拟器，确认 adb 能列出设备，并检查 `HUGOFGO_ADB` |
| 设备显示 `offline` 或 `unauthorized` | 重新连接 adb，并在模拟器中确认调试授权 |
| 分辨率被拒绝 | 改为精确 16:9 横屏，且不低于 1280×720 |
| 安装版提示 Python 依赖缺失 | 按本指南安装 Python 3.12 与安装目录中的 `cv/requirements.txt` |
| 开发版提示 Python 依赖缺失 | 按开发指南创建 `cv/.venv` 并安装固定依赖 |
| 找不到指定助战 | 确认助战列表已预筛到所需职阶，且从者/礼装条件确实存在于列表 |
| 因 AP 空白名单停止 | 这是预期保护；补充 AP 或明确修改白名单后再运行 |
| 中途接续被拒绝或走补刀 | 检查起始画面；非第 1 面第 1 回合的当前面按设计只补刀 |
| 未知画面、动作或卡面超时 | 保留运行目录与最终帧，不要反复盲点；按测试规则补回归 |

自动执行相关故障必须保留日志和截图，并按 [测试与验收](testing.md) 补充回放用例。
