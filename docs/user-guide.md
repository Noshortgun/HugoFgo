# 使用指南

这份指南面向第一次接触 HugoFgo 的 FGO 玩家，按“准备游戏和设备 → 打开作业 → 开始战斗 → 查看结果”的顺序操作。不需要先理解程序架构。

开始前请确认：目前只有指定国服种火作业完成了五项实机验收，其他作业、副本和安装版不能据此视为稳定。准确范围见[当前状态](status.md)。

## 1. 准备软件

### 安装版

安装版目前只用于验收测试，**安装、首启和完整实机流程尚未验收**。

1. 获取并运行发布者提供的 Windows NSIS 安装包。
2. 安装 64 位 Python 3.12，并按实际安装目录安装固定依赖：

   ```powershell
   py -3.12 -m pip install -r "<HugoFgo 安装目录>\cv\requirements.txt"
   ```

   也可用 `HUGOFGO_PYTHON` 指向已安装这些依赖的解释器。
3. 准备 adb 和安卓模拟器，可用 `HUGOFGO_ADB` 指定 `adb.exe`。
4. 启动 HugoFgo，打开“准备”工作区。

安装包随带 Node.js 和资源脚本，资源更新不需要另装 Node.js；**不随包附带 Python 或图库**。作业、图库、设置和运行证据位于 `%APPDATA%/com.hugofgo.desktop/` 下的 `jobs/`、`data/`、`run-settings.json` 和 `logs/`。

### 源码开发版

按[开发指南](development.md#1-环境准备)安装 Node.js、Rust、Python 和回放依赖，然后在项目目录运行：

```bash
npm install
npm run resources:update
npm run tauri dev
```

开发期的作业、资源和运行证据使用项目下的 `jobs/`、`data/` 和 `logs/`。

### 浏览器预览

`npm run dev` 只用于界面预览和作业查看。设备命令、真实运行、桌面作业库、运行历史和资源任务不可用；这些按钮在浏览器中不可用不是桌面版故障。

## 2. 准备游戏、设备与图库

### 游戏与模拟器

先按普通手动刷本的方式启动游戏，再检查：

- 当前使用国服客户端。执行器目前只接受 CN，日服和台服资源管理不代表可以执行。
- 模拟器已启用 adb 连接，HugoFgo 能检测到状态为 `device` 的设备。
- 画面为精确 16:9 横屏，且不低于 1280×720。已验收环境使用 1280×720。
- 游戏账号中的从者、概念礼装和御主礼装能够满足作业要求。

在“准备”工作区选择设备后，可以读取设备信息并截图预览。预览应当与模拟器里的游戏画面一致。

测试点击会向模拟器发送真实输入，点击预览截图也可能触发测试。不要在未知画面或涉及道具消费的页面试点。

### 图库

程序需要图库识别从者头像、概念礼装和指令卡。资源来自 Atlas Academy，下载时需要联网；识别过程不访问网络。

在“准备”工作区选择区服后：

- **检查更新**：查看远端版本。
- **增量更新**：下载新增、变更或损坏的文件，日常使用优先选择。
- **校验**：按 SHA-256 检查本地文件。
- **完整校准**：低频同步旧元数据。

空库时编队界面显示占位卡。首次更新完成后，界面会重新加载图库。CN、JP、TW 的资源分别保存在 `data/<区服>/`，字段和目录说明见[资源、素材与引用](resources.md)。

### 通道

设备通道默认使用 scrcpy。启动失败且允许回退时，界面会明确提示并改用 ADB；运行中通道中断只会安全停止，不会中途换通道继续点击。

## 3. 第一次运行：使用已验收的种火作业

目前证据最完整的路径使用 `jobs/娄希、娄希、奥伯龙.json`。先把游戏停在**助战选择页**，不要停在选卡页或未知弹窗上。其他起点的接续限制见[当前执行边界](status.md#4-当前执行边界)。

1. 在“编队”工作区打开作业库，选择该作业。
2. 对照游戏检查六个槽位、助战、概念礼装、御主礼装、三面动作、技能目标和宝具卡序。
3. 设置连续出击场数和 AP 恢复白名单。只复现验收时保持默认的“仅青铜果实”。
4. 保存作业并点击“战斗”，或切到“运行”工作区启动。
5. 启动后观察真实事件时间线、当前面与回合、正在执行的动作、完成场数、实际通道和恢复消耗。

HugoFgo 会按作业自动切换助战职阶页签，支持七个常规职阶和 Extra 页签，不需要预先手动筛选。找到助战后，它还会核对游戏里的编队；指定从者、助战概念礼装或御主礼装不符时，不会开始任务。

AP 恢复按勾选顺序尝试，先勾选的先用。勾选圣晶石时会弹出消耗确认；实际恢复前，程序还会核对游戏内的道具确认框。

### 中途需要接管

点击“停止”。停止在当前动作边界生效，不代表所有输入都在点击按钮的瞬间中止。桌面壳最多等待终端事件 30 秒，超时才终止执行器进程树；先观察面板是否进入终端状态，再决定是否手动操作游戏。

## 4. 把自己的手动打法编成作业

一份作业就是一份可保存、可分享的刷本安排：使用哪支队伍，每面每回合做什么，以及未能清场时怎样选卡。

### 选择编队

1. 在“编队”工作区选择六个槽位的从者和概念礼装，再选择御主礼装。
2. 标记助战位，并按需要指定助战从者、概念礼装或冠位条件。
3. 检查技能目标与宝具卡序引用的是否是预期槽位。

作业中的槽位编号为 0–5，动作始终通过槽位引用从者。**空槽位表示“不限制身份”**：游戏内该位置可以是任意从者，也可以为空，不是要求你必须把游戏队伍留空。

### 安排每面每回合

把原本手动刷本时的操作按顺序加入作业：

- 从者技能和御主技能。
- 己方目标选择或敌方目标切换。
- 换人。
- 宝具与攻击。
- 普通指令卡的选卡策略。

例如，“第 1 面第 1 回合先使用一技能，再使用宝具”会保存为两个有先后顺序的安排。程序执行后会重新读取画面，不会因为已经点击技能就立即假定可以选卡。

宝具可以指定卡序位置；普通指令卡按实际发牌和选卡策略处理。若本回合没有清场，**补刀策略**决定后续怎样选目标和选卡，不会主动使用未编排的技能。

### 保存与运行不是一回事

作业库可以保存当前执行器尚不支持的内容，但启动前的作业检查会拒绝运行，并尽量定位到面和回合。技能追加选择要求候选完整且索引、值一致；缺失候选或旧字符串卡色会在这里被拒绝。

保存成功后仍应检查启动诊断。完整字段见[作业格式](job-format.md)。

### 导入其他作业

作业库支持粘贴 Chaldea 分享链接或 Team ID，也支持导入本地 JSON。Chaldea 导入需要联网。导入后必须检查编队、技能目标、宝具卡序和选卡策略，不要直接启动。

`examples/sample-job.json` 用于说明文件结构，包含一个带完整候选的技能追加选择；它仍**不是首个可运行作业示例**。

## 5. 理解运行中的不同结果

### 完成

达到固定场数，或者清 AP 阶段到达 AP 恢复页且没有使用恢复道具。末场结束后不会多点“连续出击”。

### 补刀与计划外自动战斗

- **补刀**：作业动作执行完但没有清场，程序按既定规则继续选卡，直到该面结束或达到安全上限。
- **计划外自动战斗**：实际战斗与作业预期不同，原动作无法执行，但当前画面和可用操作仍能确认时，程序可转为完成当前场，并提示原因；下一场恢复原始作业。它不同于补刀，详细边界见[领域术语](../GLOSSARY.md)。

### 手动停止

你主动请求结束，停止在动作边界生效。

### 失败或安全停止

程序无法确认画面、动作、卡面或恢复条件时会停止。例如：

- AP 不足，但恢复白名单为空：不会改选圣晶石或其他果实。
- 恢复确认框里的道具与待确认项目不一致：不会确认消耗。
- 从者身份、卡色、宝具归属或战斗进度持续无法确认：不会猜测。
- 出现未知页面或未支持的弹窗：不会用固定坐标试探关闭。

战斗中途接续时，如果程序无法确认当前面已经执行过哪些动作，当前面只补刀，下一面才恢复作业动作。

## 6. 查看记录与故障证据

在“记录”工作区可以查看作业、设备、通道、区服、起止时间、耗时、完成场数、结果和恢复消耗。选择一条记录后，可以查看最近事件、识别统计和证据路径，也可以打开证据目录或复制路径。

每次运行的完整证据位于 `logs/farm/<运行ID>/`：

| 文件 | 可以回答的问题 |
| --- | --- |
| `summary.md` | 每场、每面、每回合计划做什么，实际点击了什么，哪些动作获得画面确认 |
| `events.jsonl` | 状态、动作、警告和终端事件按什么顺序发生 |
| `result.json` | 最终结果、停止原因、进度和恢复消耗是什么 |
| `job.json` / `plan.json` | 原始作业与执行计划是什么（已生成时） |
| `observation.json` | 最后一帧被识别成了什么 |
| `failure.png` | 非完成运行结束时游戏显示了什么（可用时） |

动作已经点击不等于游戏已经受理，摘要会区分输入与后续画面确认。三卡提交、助战滑动与“列表更新”等关键动作还会保存对应帧和观察 JSON，供复核识别、卡序、点击与列表到底判断。需要为既有运行重新生成摘要时，执行 `python -m executor.session.summary <运行目录> [--job <作业.json>]`；Windows 源码版可按测试文档使用 `cv/.venv/Scripts/python.exe`。

全局历史索引是 `logs/run-history.jsonl`。安装版文件位于应用数据目录，开发版位于项目目录。反馈故障时保留整个运行目录，不要只截取一句错误。

## 7. 故障排查

| 现象 | 先检查什么 |
| --- | --- |
| 从者或礼装图片缺失 | 在“准备”中增量更新，再执行校验；开发版也可运行 `resources:update` / `resources:verify` |
| 资源更新失败 | 检查 Atlas Academy 与 GitHub 网络，保留任务输出后重试 |
| 作业保存、设备或资源按钮不可用 | 确认使用桌面版，而不是浏览器预览 |
| 没有发现设备 | 启动模拟器，确认 adb 能列出设备，并检查 `HUGOFGO_ADB` |
| 设备显示 `offline` 或 `unauthorized` | 重新连接 adb，并在模拟器中确认调试授权 |
| 分辨率被拒绝 | 改为精确 16:9 横屏，且不低于 1280×720 |
| 安装版提示 Python 依赖缺失 | 按本指南安装 Python 3.12 与安装目录中的 `cv/requirements.txt` |
| 开发版提示 Python 依赖缺失 | 按开发指南创建 `cv/.venv` 并安装固定依赖 |
| 找不到指定助战 | 确认作业要求的从者和礼装确实会出现在当前助战列表；职阶页签由程序自动切换 |
| 因 AP 空白名单停止 | 这是预期保护；补充 AP 或明确修改白名单后再运行 |
| 中途接续被拒绝或走补刀 | 检查起始画面；无法还原当前面动作进度时按设计只补刀 |
| 未知画面、动作或卡面超时 | 保留运行目录与最终帧，不要反复盲点；按测试规则补回归 |

自动执行相关故障必须保留日志和截图，并按[测试与验收](testing.md)补充回放用例。想理解这些保护为什么存在，继续阅读[工作原理](how-it-works.md)。
