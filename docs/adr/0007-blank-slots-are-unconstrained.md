# 空槽位表示不限制，而不是要求游戏内为空

Status: accepted（2026-11-24 与用户确认；2026-11-28 与用户确认修订，同日补充主动删除与唯一助战规则）

## Context

部分作业只需要使用一至两名从者通关，但游戏本身仍要求至少三名实际从者。过去把作业空槽位理解成“必须为空”，并据此要求前三槽完整，会拒绝本可运行的作业，也无法表达“这里放谁都行”。

同时，作业中的“任意从者”和实际存在的空从者容易被混为一谈：前者是作业不限定身份，后者是游戏画面中没有从者。

任意助战也需要与运行时身份区分。任意助战只约束助战选择阶段，从者身份不限，概念礼装可独立指定；实际选中后，该位置中的从者与其他空槽位实际从者都按任意从者处理，不再设置助战专用战斗规则。

## Decision

作业的 0–5 都是逻辑槽位。没有指定从者的槽位是空槽位，统一表示**不限制**：游戏内该位置可以是任意从者，也可以没有从者。文件不新增“任意从者”字段，空名和省略项都归一为空槽位。

编队核对只在用户点击战斗后、每次运行开始时执行一次，只核对作业指定从者的身份与槽位，包括指定候补；空槽位直接跳过，不核对也不记录其中实际从者的身份。任意助战同样不核对或记录实际从者身份；只有作业显式指定助战概念礼装时，才按实际助战槽核对该礼装。

任意从者可按原始槽位参与主动换人，也可作为指定从者技能的己方目标。执行目标技能前必须确认该槽位实际有人，无法确认时按计划偏离处理。换人和己方目标引用不再仅因槽位未指定身份而被拒绝。

任意从者不能承担固定技能、固定宝具、固定普通卡、宝具卡序或从者优先级等依赖具体从者身份的编排。旧作业导入时，这类非法引用必须保留显示为错误，修复前禁止战斗；这与用户在编队页主动删除从者不同，后者会清除该从者的全部关联操作，不让旧操作在新从者上复活。

选卡采用两层硬顺序：所有指定从者优先于空槽位中实际出现的任意从者，不区分指定从者是否被作业使用。非固定卡序的自动选卡可以使用卡色与可操作性稳定、但从者身份未知的任意从者卡，不要求额外识别实际从者；固定卡序仍必须确认指定从者身份，未知卡不得替代。

指令卡牌组跟踪只用于识别质量的非阻塞告警，不作为自动选卡的额外门槛。普通牌组按完整十五卡周期统计；锁卡技能按 Atlas 技能效果识别，在技能生效确认后校验重抽的下一手，不套用普通牌组统计。

任意助战作业不保存旧的从者身份字段，显式保留 `supportRequired: false`，避免导入导出后变回指定助战。正常编队始终有且仅有一个助战槽。零助战旧作业在导入前由用户选择现有槽位作为助战，取消选择则取消导入；异常导入出现多个助战槽时启动前拒绝。

## Consequences

- 作业不需要为了通过校验而补满前三名从者；游戏自身负责最少从者数量限制。
- 同一份作业可以适配空槽位中不同的实际从者，补刀与自动选卡仍可使用这些从者的普通卡和宝具。
- 任意从者可以换入、换出或接收指定从者的己方技能；固定技能、宝具和卡序仍要求指定身份。
- 自动选卡可能把识别失败的指定从者卡当成任意从者卡使用。该风险由牌组与锁卡告警暴露，不能宣称告警机制保证了每次自动选卡的从者优先级正确。
- 编队核对不能再把空槽位或任意实际从者当成不匹配，也不能通过压缩前排来改变槽位含义。
- 主动清空普通从者时必须同时清除礼装等专属字段及全部关联操作，避免空槽位携带不可见条件；删除指定助战或切换为任意助战时清除旧从者身份、关联操作和助战筛选条件，但在原槽保留任意助战，不得变成零助战。一键清空编队后在第一槽保留任意助战。具体拖动与清空交互见需求 F1.13–F1.15 和票据 71。
- 无法在作业中要求“这个槽位必须为空”；若未来确有该需求，需要新增显式字段而不是复用空名。

## Considered Options

- **三态槽位：指定／任意／必须为空**：表达力更强，但会增加 UI 与文件复杂度，且 Chaldea 导入没有对应状态，未采用。
- **继续要求前三槽完整**：会拒绝用户实际需要的一至二人作业，未采用。
- **空槽位继承编辑器当前从者**：会让同一 JSON 在不同会话得到不同含义，未采用。
- **任意助战记录并绑定实际从者 ID、职阶和礼装**：会把选择条件扩展成运行时身份记录，与空槽位不核对、不记录身份的语义冲突，2026-11-28 由用户否决。
- **未知卡必须有正面证据才能参与自动选卡**：能避免指定从者卡被降级，但会增加等待和安全停止；最终选择允许自动选卡使用稳定未知卡，只用牌组跟踪发出告警。固定卡序不放宽。
- **锁卡期间继续套普通十五卡统计**：其他从者不出卡是锁卡的正常结果，会误报或漏报；改用技能生效后的下一手专用校验。
