# 技能追加选择采用索引驱动的通用菜单状态机

Status: accepted（2026-11-28 与用户确认）

## Context

技能追加选择覆盖 14 个从者 ID、16 个技能，但真实菜单并不统一。其中 13 个来自 Atlas `SelectAddInfo`，选项顺序就是按钮数组顺序；另外三个宝具变体菜单各不相同：卫宫只有 Arts/Buster 两项，太空伊什塔尔是 Quick/Arts/Buster 三项，BB 迪拜是攻击类型/防御类型两项且两者都是 Arts。

用户明确要求交付后全部当前技能即可使用，不接受逐技能适配，也拒绝运行期 OCR 和不固定的长延迟。逐从者实机采集素材同样不可行。旧生成器把三个宝具菜单统一写成 Arts/Buster/Quick，既错误又无法用颜色区分 BB 迪拜的两个选项。

## Decision

#66 以全部 16 个当前技能可执行作为完成条件，作业 Schema 不变。图库索引生成内部追加选择描述，包含技能 ID、菜单形态、真实选项数量与顺序、选项索引/值/标签、可用条件及后续目标阶段。

`selectAddInfo` 的索引以 Atlas 按钮数组为语义真相；同一规则扩展到全部宝具变体菜单。生成器必须按真实菜单生成选项：读取 `excludeTdChangeTypes` 与 `selectTreasureDeviceInfo`，不得再把所有 `tdTypeChange` 技能统一写成三种卡色。旧作业中的错误字符串卡色或缺失候选在编译时拒绝，不自动迁移。

执行器新增追加选择阶段：

1. 按动作上下文识别追加选择菜单、实际按钮区域及可用状态，不使用固定屏幕坐标，也不做 OCR。
2. 按配置索引或图片匹配选择唯一选项；文字标签只用于编辑与诊断。
3. 点击后确认菜单离开，再按实际画面进入普通目标阶段或等待战斗恢复。
4. 只有整个流程完成后才推进动作序号。

菜单未出现、形态或数量不符、选中项不可用、点击后没有新画面、后续目标或战斗状态未恢复时安全停止，不回退默认项、不重复点击原技能。

运行期素材按菜单形态维护，不按从者或选项逐份采集。全部 16 个技能必须有离线元数据用例；每种形态使用代表性真实画面素材；三种宝具变体按真实选项数量验证。游戏内部效果只对有稳定证据的代表项验收。当前作业默认使用已解锁的技能强化版；没有 `skillId` 字段，点击后未出现预期菜单时按技能版本不匹配停止。

## Consequences

- 13 个文字菜单不需要 22 份文字模板，运行速度不依赖 OCR。
- 宝具变体菜单统一按按钮索引执行，不再需要判断选项颜色；BB 迪拜的攻击/防御选择也因此可支持。
- 国服文字菜单在选项左侧固定提供系统“取消”，因此识别到“取消 + N 个选项”时要按选项数跳过首按钮；宝具卡菜单没有该额外按钮，不能无条件套用偏移。
- 若游戏静默改变同一菜单的选项顺序，纯索引无法识别内容变化；只能依靠数据更新、菜单数量保护和后续效果暴露。这是为了全量覆盖、无 OCR 且不逐技能采素材而接受的残余风险。
- 菜单形态继续变化时，安全停止比“永远能点”更重要；未知形态必须保持不可执行。
- 图库生成、前端导入和执行器必须共同消费同一份内部描述，不能各自推导按钮顺序。

## Considered Options

- **OCR 识别选项文字**：能核对内容，但运行开销不可接受，且引入字体、区服和特效遮挡问题，未采用。
- **每个文字选项制作模板**：能核对语义，但需要维护 22 份以上素材，新增技能仍要适配，未采用。
- **逐从者硬编码或固定坐标**：实现直接，但无法跨分辨率和布局变化，也满足不了安全停止要求，未采用。
- **先交付一个宝具卡色试点，再逐步扩展**：风险较低，但用户明确要求一次交付全部当前能力，未采用。
