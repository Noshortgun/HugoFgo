# 执行器统一为 Python 工作进程，Rust 只做桌面壳与进程管理

Status: accepted（2026-11-19 与用户确认：前端与 Rust 壳复用，执行器新写为 Python 子进程，自带设备层）

重构后只保留一个执行器：Python 工作进程，由 Tauri 启动、停止并接收状态推送。Rust 保留窗口、进程生命周期和 IPC，不实现任何战斗逻辑。

注意：选择 Python 的理由**不是**保留旧代码——旧后端已决定全部重写。真正的理由是图像识别与 OCR 生态（OpenCV、RapidOCR）在 Python 侧成熟，且离线回放这类"截图进、动作出"的验证写法在 Python 里成本最低。

## Considered Options

- **全 Rust 重写（含 OCR 与模板匹配）**：桌面端集成最干净、单进程分发最简单，但 OCR 需要另找运行时或外部进程，回放验证体系也要从零搭建，工作量明显更大。
- **Node/TypeScript 执行器**：与前端同语言，但图像与 OCR 库生态弱于 Python，且仍需独立进程。
- **前端直接调用 Python 长驻服务**：引入端口、鉴权与打包分发问题，桌面版难以离线运行。

## Consequences

- 若改为全 Rust，则 ADR-0001 作废，桌面桥接票据简化为进程内调用，但图像识别与回放工作量显著上升。
