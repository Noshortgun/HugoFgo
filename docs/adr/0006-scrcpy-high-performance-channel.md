# 高性能实机通道采用 scrcpy，ADB 保留通用回退

Status: accepted（2026-11-22 与用户确认）

自动战斗需要缩短取帧与输入延迟。ADB 每次截图和输入都要启动命令，实测截图约 382–399 ms；现有 LDPlayer 原始帧通道虽然约 13 ms，但只支持 Windows + LDPlayer 且没有完整输入链。因此新增 scrcpy 持续视频流与输入作为高性能通道，ADB 与 scrcpy 共用同一套动作状态机，不分叉战斗行为。

scrcpy 首版由用户显式选择，实机验收后再设为支持设备上的默认通道。启动失败可在明确提示后回退 ADB；运行中视频流或控制中断必须在动作边界安全停止，不自动跨通道续跑。

## Considered Options

- **只优化 ADB**：保留最广兼容性，但单次截图成本无法达到本次操作速度目标。
- **只接通 LDPlayer 原始帧**：复用已有适配器，但会把高性能能力限定在单一平台和模拟器。
- **ADB 与 scrcpy 各自维护战斗逻辑**：可以分别调参，但会让动作与安全回归重复维护，因此拒绝。

## Consequences

- 设备层需要管理 scrcpy 生命周期、帧新鲜度、输入会话与中断证据；这些能力不能进入作业格式。
- 感知与执行器继续依赖统一帧和设备接口，不按通道复制动作决策。
- 高性能通道未通过实机验收前不得默认启用；ADB 只承诺行为一致，不承诺同等速度。
