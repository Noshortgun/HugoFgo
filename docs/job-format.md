# 作业格式 v1

作业是包含编队、御主礼装、各面各回合动作与选卡策略的 JSON 文件。推荐用可视化界面创建和编辑，再导出备份或分享。

机器可读契约是 `schemas/job-v1.schema.json`，完整示例是 `examples/sample-job.json`。结构合法不代表当前执行器已支持运行其中的全部能力，实际接通情况见 [当前状态](status.md)。

## 1. 顶层字段

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `version` | 常量 `1` | 作业格式版本，必填 |
| `name` | 字符串 | 可选显示名称 |
| `mysticId` | 非空字符串 | 御主礼装标识，必填 |
| `enemyCount` | `3` 或 `6` | 敌方阵型规模，必填 |
| `formation` | 数组 | 编队槽位，必填 |
| `strategy` | 对象 | 全局补刀策略，必填 |
| `strategyByWave` | 对象 | 可选的按面补刀策略覆盖 |
| `waves` | 1～3 项数组 | 面和回合定义，必填 |
| `warnings` | 字符串数组 | 可选警告信息 |
| `provenance` | 任意 JSON | 可选来源信息，不作为执行动作 |

Schema 不允许未列出的顶层字段。桌面编辑器显式保存时会保留原文件中的额外顶层字段，以免导入导出意外丢数据；但“编辑器保留”不等于“执行器接受”，含额外字段的文件仍需通过 Schema 与编译器校验才能运行。

## 2. 编队与槽位

`formation` 中每项至少需要：

```json
{ "slot": 0, "name": "阿尔托莉雅" }
```

槽位编号为 0–5，动作通过槽位引用从者，不使用界面会话中的临时 ID。常用可选字段：

| 字段 | 含义 |
| --- | --- |
| `svtId`、`npId` | 从者与宝具的数据标识 |
| `limitCount` | 再临阶段，1–4 |
| `role` | 职阶显示信息 |
| `support` | 是否为助战位 |
| `supportRequired` | 是否指定助战从者身份；与概念礼装条件独立 |
| `grandRequired` | 是否必须为冠位助战 |
| `ce`、`ceId` | 概念礼装名称与标识 |
| `grandCe`、`grandCeIds` | 冠位助战的三类礼装条件 |

`support: true` 且 `supportRequired: false` 表示**任意助战**：只要求选择一个助战，不限制从者身份，`ce`／`ceId` 仍可独立指定。任意助战不保存 `name`、`svtId`、`npId`、`role`、`limitCount` 等旧从者身份字段，导出必须显式写出 `supportRequired: false`，导入不得因该字段缺省或从者名为空而把任意助战变成指定助战、普通空位，或丢弃其礼装条件。实际选中的从者进入战斗后按任意从者处理，不把实际身份写回作业。编队最多一个 `support: true` 槽位，导入出现多个助战槽时启动前拒绝。

`name` 为空或纯空白的槽位是**空槽位**，表示“不限制”：游戏内该位置可以是任意从者，也可以没有从者。空槽位不要求游戏内为空，也不是一种需要用户选择的“任意从者”配置。文件可以省略空槽位；导入时省略项与显式空名都归一为空槽位，不继承编辑器当前编队。导出时写全 0–5 六个槽位。

编队不要求前三槽都指定从者；游戏本身仍要求至少三名实际从者。清空槽位时应同时清除该槽位的从者、概念礼装、助战等专属字段。

编译器会拒绝重复槽位，以及显式引用空槽位的固定技能、宝具、宝具卡序、固定指令卡和从者优先级。空槽位可以按槽位参与主动换人，也可以作为指定从者技能的己方目标；执行时必须按画面确认该位置实际有人。空槽位中的实际从者只能由运行时自动使用普通卡和宝具，不能承担固定技能或宝具编排。

## 3. 面、回合与动作

`waves` 必须包含 1～3 面。游戏关卡最少一面、最多三面；导入超过三面的作业会报错，编辑器与执行器都不会静默截断。

每个 `waves` 元素包含：

- `turnCount`：回合数，必须与 `turns` 数组长度一致。
- `target`：保留的作业与界面元数据，范围 1–6；执行器不会据此自动切敌，需要切敌时必须在回合 `actions` 中显式添加 `target` 动作。
- `turns`：回合数组，每项包含 `actions`，可另含 `npPositions` 和 `attack`。

`actions` 按数组顺序执行。每个动作需要 `kind`、`title`、`detail` 和 `icon`，其中后三项用于显示。`kind` 可取：

| `kind` | 含义 | 常用附加字段 |
| --- | --- | --- |
| `skill` | 从者技能 | `memberSlot`、`skill`、`playerTargetSlot`、`secondarySelection` |
| `master` | 御主技能 | `skill`、`playerTargetSlot` |
| `spell` | 令咒 | 目标或追加选择字段 |
| `attack` | 从者宝具攻击 | `memberSlot` |
| `target` | 切换敌方目标 | `enemyTarget` 或 `fromTarget`、`toTarget` |
| `orderChange` | 换人 | `swapOutSlot`、`swapInSlot` |

`skill` 从 0 开始计数，0 表示一技能。从者技能与宝具 `attack` 必须带有有效的 `memberSlot`，缺失或指向空槽位都不可执行。`playerTargetSlot` 可以省略；出现时可以指向指定从者或任意从者，本格式不判断某技能是否本应有目标。任意从者目标在执行时必须由画面确认该位置实际有人，无法确认时按计划偏离处理。敌方技能作用于当前选中的敌人，不保存“敌方槽位”，切换敌人由独立的 `target` 动作完成。

换人上下场槽位不能相同，每场战斗最多安排一次换人服主动换人；作业始终用原始 0–5 号槽标识从者，程序维护其当前在前排或替补的位置。`secondarySelection` 保存技能或宝具的追加选项，旧文档称二次选择，例如暴击星消耗、攻击/防御宝具变体和卡色。`index` 是作业选项顺序，`value/label` 必须与 `options[index]` 一致，`options` 不得缺失。执行器识别当前菜单的实际按钮区域；文字菜单最左的系统“取消”不计入 `options`，执行器会按选项数自动跳过它。数量不符、灰显、菜单未出现或未关闭都会停止。旧字符串卡色值、没有对应真实技能的类型在编译时拒绝。

导入含空槽引用的旧作业时，换人与己方目标引用按任意从者规则保留为可编排内容；固定技能、宝具、卡序和从者优先级等非法引用必须原样保留并标记为不可执行，不得静默删除或过滤。自我退场与自动补位不在作业字段中声明：执行器按画面确认实际结果，前端则可根据 Atlas 中的技能／宝具效果推演计划前排，两者都不得把“预期退场”写成“必然退场”。

## 4. 宝具卡序与指令卡

回合中的 `npPositions` 以从者槽位为键，值可以是：

- `1`、`2`、`3`：宝具卡在该回合卡序中的位置。
- `"auto"`：自动安排宝具卡位置。

```json
"npPositions": { "0": 1, "3": "auto" }
```

`npPositions` 与宝具动作只能引用指定从者，不能引用空槽位。空槽位中实际从者的宝具不进入固定卡序，只能在补刀或计划外自动战斗时按运行时规则自动选择。

回合中的 `attack` 描述旧版普通指令卡选择。当前前端不提供固定卡序编辑；导入时会忽略该字段并提示改用选卡策略，再次保存时移除。

| `mode` | 行为语义 |
| --- | --- |
| `strategy` | 不指定固定卡序，使用补刀策略 |
| `prefer` | 尽量按给定卡序，发牌不符时回落到补刀策略 |
| `verify` | 必须匹配给定卡序，不匹配时停止并提示 |

`cards` 中每项包含从者 `slot`、卡色 `type`（`buster / arts / quick`），可选 `deckIndex` 用于记录牌库中的具体卡片。

## 5. 补刀策略

全局 `strategy` 和 `strategyByWave` 中的覆盖项使用相同结构：

| 字段 | 含义 |
| --- | --- |
| `allowNp` | 补刀时是否允许使用宝具 |
| `servantOrder` | 普通指令卡按从者名称排列的先后顺序，不包含宝具卡 |
| `servantOrderSlots` | 普通指令卡按槽位排列的先后顺序，可区分同名从者，不包含宝具卡 |
| `cards` | `buster / arts / quick / balanced` 选卡倾向 |
| `colorPriority` | 卡色优先顺序 |
| `strategyOrder` | `servant / cards / crit / affinity` 各策略的比较顺序，默认 `servant → cards → affinity → crit`；未列入的 `affinity` 保持末位兜底 |

普通指令卡采用两层硬顺序：所有指定从者优先于空槽位中实际出现的任意从者，不区分指定从者是否被作业使用。指定从者内部按作业顺序以及主动换人、自动补位的接替规则排列；卡色、暴击、克制和 `strategyOrder` 只在同一层内部比较，不能跨层逆转该顺序。空槽位任意从者的普通卡即使能够识别，也始终排在指定从者之后。非固定卡序的自动选卡可以使用卡色与可操作性稳定、但从者身份未知的任意从者卡；牌组统计只产生识别质量告警，不额外阻塞选卡。固定卡序仍必须确认指定从者身份。

普通指令卡按卡序位置逐张选择：每个位置先在同一层内按 `strategyOrder` 比较当前剩余普通卡，选定并移除一张后，再选择下一位置。已保留的宝具卡不参与普通卡排序；完全并列时选择画面中最靠左的卡。宝具固定在第二或第三卡序位置时，只占用该位置，之前的普通卡选完后，后续位置继续按同一规则选择剩余普通卡。不得改为一次性比较整组普通卡组合，也不得在选定普通卡后按屏幕位置重新排序。

`allowNp` 只控制补刀时是否允许自动使用宝具。空槽位任意从者与未编排宝具的指定从者受该开关控制；轮到该从者时，宝具优先于其普通卡，但不越过更靠前的从者层。作业显式 `attack`／`npPositions` 指定的宝具始终执行，不受 `allowNp` 取消。计划外自动战斗使用独立规则，不沿用补刀的 `allowNp` 与固定卡位。

`strategyByWave` 的面编号键为 `"1"`、`"2"`、`"3"`；值为 `null` 表示该面没有独立覆盖。

`affinity` 读取卡面上的克制/抵抗标识，结果按当前选中的敌方目标判定；需要切换攻击目标时，必须在回合 `actions` 中显式加入 `target` 动作，执行器不会因作业字段 `target` 自动切敌。

## 6. 本地校验

```bash
python -m executor.domain examples/sample-job.json
python -m executor.domain examples/sample-job.json --json
```

非法作业会返回非零退出码，并用 JSON 路径、面或回合定位错误。校验覆盖 Schema 结构、回合数、重复槽位、空槽位引用和换人槽位冲突等规则。
