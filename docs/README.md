# 文档地图

先按你的目标选择文档，不需要从架构或术语开始读。历史记录和票据快照不能代替当前文档。

## 我想第一次使用

1. [使用指南](user-guide.md)：准备游戏与设备，运行第一份作业，查看结果和故障证据。
2. [当前状态](status.md)：确认当前作业、区服、设备和安装版是否在已验收范围内。
3. [工作原理](how-it-works.md)：用刷本过程中的游戏画面理解各个模块。

## 我想理解软件怎样工作

- [工作原理](how-it-works.md)：面向新读者，解释“计划做什么、画面看到什么、下一步能否安全执行”。
- [架构与接口](architecture.md)：面向开发者，提供进程模型、模块边界、命令、事件和文件契约。
- [领域术语](../GLOSSARY.md)：查询作业、编队、补刀、计划偏离和安全停止等严格定义。
- [架构决策](adr/)：了解重要设计取舍及其背景。

## 我想编写或修改作业

- [使用指南：把自己的手动打法编成作业](user-guide.md#4-把自己的手动打法编成作业)：从游戏操作理解编队、动作和选卡策略。
- [作业格式](job-format.md)：检查 JSON 字段、槽位引用、宝具卡序和补刀语义。
- [当前状态](status.md)：确认哪些动作已经实现或验收。Schema 合法不等于可以运行。

## 我想参与开发

- [开发指南](development.md)：安装环境、预检、构建、分支和 issue 流程。
- [架构与接口](architecture.md)：查找代码边界和本地集成入口。
- [测试与验收](testing.md)：运行离线验证、回放和实机验收，理解不同证据能证明什么。
- [工程脚本索引](../scripts/README.md)：查找脚本入口、输出和用途。
- [资源、素材与引用](resources.md)：处理 Atlas 素材、模板、截图和引用关系。
- [需求基线](requirements.md)：核对产品目标、需求、发布门槛和范围。

## 文档分层

| 层次 | 文档 | 回答的问题 |
| --- | --- | --- |
| 场景化导读 | `README.md`、[使用指南](user-guide.md)、[工作原理](how-it-works.md) | 我该怎样使用？软件刚才替我做了什么？ |
| 精确参考 | [作业格式](job-format.md)、[架构与接口](architecture.md)、[资源](resources.md) | 字段、接口、协议和路径的准确规则是什么？ |
| 当前事实与产品基线 | [当前状态](status.md)、[需求基线](requirements.md)、[领域术语](../GLOSSARY.md)、[架构决策](adr/) | 现在支持什么？为什么这样设计？ |
| 工程协作 | [开发指南](development.md)、[测试与验收](testing.md)、[Agent 约定](agents/) | 怎样修改、验证和发布？ |
| 历史记录 | [历史进展](../HANDOFF.md) | 项目过去经历了哪些实施与验证阶段？ |

导读可以引用和解释规则，但不另建一套字段、接口或验收结论。发现冲突时，更新对应的权威文档，而不是只改导读。

## 单一事实来源与维护责任

| 权威文档 | 负责维护的内容 | 需要更新时 |
| --- | --- | --- |
| [当前状态](status.md) | 当前可用能力、未接通功能和已知限制 | 功能接通、验收结果或限制变化 |
| [使用指南](user-guide.md) | 当前版本可执行的使用流程与故障处理 | 用户操作或错误提示变化 |
| [工作原理](how-it-works.md) | 面向新读者的模块职责与游戏情景解释 | 模块分工或用户可见行为变化 |
| [作业格式](job-format.md) | 作业 v1 的字段语义与示例 | Schema、导入或导出语义变化 |
| [开发指南](development.md) | 环境、预检、构建、分支和 issue 流程 | 工程命令或协作规则变化 |
| [工程脚本索引](../scripts/README.md) | 脚本分类、入口和输出用途 | 新增脚本或命令语义变化 |
| [资源、素材与引用](resources.md) | Atlas 素材、模板、截图、实机证据的分类和引用合约 | 资源类别、引用关系或资源命令变化 |
| [测试与验收](testing.md) | 测试入口、证据层级、回放、素材和实机验收规则 | 验证方式或素材规则变化 |
| [需求基线](requirements.md) | 产品目标、需求、发布门槛和范围 | 已确认产品决策变化 |
| [架构与接口](architecture.md) | 当前模块边界、Tauri/CLI/文件契约和目标目录 | 架构决策或模块契约变化 |
| [领域术语](../GLOSSARY.md) | 项目统一用词 | 领域概念或命名变化 |
| [架构决策](adr/) | 单项重要决策及其背景 | 新决策被确认或旧决策被取代 |
| [Agent 约定](agents/) | Agent 工具、领域文档和 issue tracker 规则 | 协作工具或规则变化 |
| [历史进展](../HANDOFF.md) | 按阶段追加的实施与验证记录 | 阶段收尾时追加，不改写旧条目 |

- 当前能力以 `docs/status.md` 为准，README 只保留入口和必要警告。
- 当前接口以代码和[架构与接口的当前契约](architecture.md#3-当前接口契约)为准；架构中的未来目标必须显式标注。
- 产品需求以 `docs/requirements.md` 为准，不另维护一份需求副本。
- 作业结构以 `schemas/job-v1.schema.json` 为机器可读契约，`docs/job-format.md` 负责解释字段。
- 已发布票据以 GitHub issue 为准，本地票据源用于修改和发布，规则见 [Issue tracker](agents/issue-tracker.md)。

`.scratch/backend-rebuild/current-state.md` 是 2026-11-19 的历史快照。`.scratch/backend-rebuild/spec.md` 是重构票据的原始规格快照；其中与当前需求或架构不同的内容，以文档地图中的权威文件为准。
