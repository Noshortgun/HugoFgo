# HugoFgo 需求基线

版本：v1 草案（2026-11-19）。本文是产品级需求基线，取代之前只覆盖后端的描述；术语以 `GLOSSARY.md` 为准。

## 1. 产品目标

让国服 FGO 玩家在 Windows 桌面上，用可视化方式编队、编排作业，然后一键让模拟器自动刷本；过程可见、随时可停、出错留有证据。

## 2. 用户与使用环境

- 单人使用，Windows 桌面，安卓模拟器（当前实测 LDPlayer，1280×720）。
- 支持国服、日服、台服；**首期只交付国服**，其余区服需要各自的素材采集与实机验收（见 ADR-0003）。
- 区服是设备的属性；识别配置与图库按区服隔离，作业不带区服、可跨服分享。
- 除"资源更新"和"Chaldea 链接导入"外，全部功能离线可用。
- 未来可能扩展到 Web、移动、多开，但本轮不预先实现，只要求架构不堵死这些方向。

## 3. 功能需求

### F1 编队与作业编排（已有，保留）

- F1.1 六槽位编队，支持从者、概念礼装、御主礼装选择与再临切换。
- F1.2 助战位指定；同名同职阶从者能区分，同名不同从者不混淆。
- F1.3 按 1～3 面、按回合编排动作：从者技能、御主技能、换人、敌方目标切换、攻击；超过三面的作业拒绝导入。
- F1.4 宝具卡序位置可指定；普通指令卡统一由选卡策略处理。
- F1.5 补刀策略支持全局配置与按面覆盖。
- F1.6 选卡策略支持克制判据，默认顺序为从者顺序 → 选卡倾向 → 克制 → 暴击率；克制按当前选中敌人的卡面标识判定，不按职阶推算。
- F1.7 不支持的动作保留可编辑，但必须在启动前明确拦截并定位；旧作业中的固定卡序在导入时忽略并提示。
- F1.8 作业空槽位表示“不限制”，不是要求游戏内为空：实际可以是任意从者或没有从者。作业可以不指定前排全部三名；游戏自身仍要求至少三名实际从者。
- F1.9 清空槽位时同时清除该槽位的从者专属设置；引用该空槽位的旧动作、目标、宝具卡序与从者顺序必须保留并标错，修复前禁止战斗，不得静默删除或改成无目标动作。
- F1.10 计划前排按主动换人与可识别的自我退场动作推演；自我退场的从者从下一回合起不再显示，候补队列首位自动补入其位置。删除该动作后仅重算作业预览；下一场副本才恢复初始编队。
- F1.11 Chaldea 导入复用同一套计划前排推演，把退场补位后的位置动作映射回正确从者；资料不足无法确认补位时不猜测，保留作业并提示导入后检查。
- F1.12 每场战斗最多安排一次换人服主动换人；被换下者进入替补席，退场自动补位不受该次数限制。作业槽位编号始终指原始编队槽，程序另行维护每名指定从者当前在前排还是替补。

### F2 作业库（格式不变，存储重写）

- F2.1 作业保存、列表、打开、删除；以 JSON 文件存于 `jobs/`。
- F2.2 作业导入导出为单个 JSON 文件，可跨设备、跨会话分享。
- F2.3 支持从 Chaldea 分享链接或 Team ID 导入（需联网）。
- F2.4 作业格式 version 1 的字段语义与槽位引用方式保持不变。
- F2.5 打包后的桌面版中，F2.1–F2.2 不依赖开发服务器。
- F2.6 导入与再次保存不得丢弃 Schema 允许的面、回合或动作数据；执行不支持的内容由运行前检查报告。

### F3 资源数据管理（管线保留，入口重写）

- F3.1 从者、礼装、御主礼装元数据与图片可从 Atlas Academy 增量更新。
- F3.2 更新只下载新增、变更或损坏的文件，写入原子化。
- F3.3 每个文件有 SHA-256 校验；缺失或损坏可被发现并修复。
- F3.4 图库不随安装包分发；首次启动可空库运行（占位卡），用户主动下载。
- F3.5 更新、校验、完整校准在桌面版中可用，不依赖开发服务器。
- F3.6 图库与资源清单按区服分目录、各自独立缓存，切换区服不重下。

### F4 设备连接

- F4.1 列出 adb 可见设备，显示型号、分辨率、连接状态。
- F4.2 截图预览，确认执行器看到的是同一画面。
- F4.3 adb 路径与设备可配置；配置缺失时给出可操作的错误提示。
- F4.4 坐标以 1280×720 为基准换算；仅支持精确 16:9 横屏且不低于 1280×720，其他分辨率明确拒绝，不盲点（ADR-0005）。
- F4.5 设备配置包含区服；未配置或该区服未支持时，不允许直接开跑。
- F4.6 scrcpy 为默认通道，ADB 作为启动失败时的可见保底；运行中通道中断只安全停止。已保存的显式 ADB 选择不被静默覆盖。

### F5 自动执行（核心，全部新写）

- F5.1 执行器完整执行作业的多面多回合动作，不只执行每面首回合。
- F5.2 技能目标、御主技能目标、换人、宝具卡序严格按作业执行。
- F5.3 未清场时按补刀策略继续，直到该面结束或达到安全上限。
- F5.4 执行器只依据画面状态行动；每次动作后重新识别确认。
- F5.5 未知画面、从者详情、意外冠位页、意外弹窗一律安全停止。
- F5.6 助战按作业要求搜索与选择；从者头像与概念礼装均使用图像匹配，助战选择不使用文字 OCR。已处于所需职阶时不重复切换，先逐页向下翻找，翻到底仍无目标才刷新列表，找不到则停止。
- F5.7 固定场数连续出击；末场结束后不多点"连续出击"。可选"场数刷完后清空剩余 AP"，此阶段不再使用任何恢复道具，AP 归零即完成。
- F5.8 作业包含执行器不支持的能力时，运行前明确报错并定位到面与回合。
- F5.9 从已知画面启动时按可确认的运行进度接续，不要求固定起始页。新启动处于战斗或选卡页时，必须能确认面、回合及本回合已执行动作；无法确认时安全停止，不重复放技能或猜测选卡进度。无法还原此前换人与补位历史、但能确认当前战斗画面时，按 F5.13 进入计划外自动战斗。
- F5.10 AP 不足时按恢复策略补足：用户白名单（4 种苹果 + 圣晶石），默认仅允许青铜苹果，选择持久化；每次消耗计数并在面板可见。详见 ADR-0004。
- F5.11 用户点击战斗后，每次运行只核对一次编队：核对作业指定从者的身份与槽位，包括指定候补；空槽位直接跳过，不核对也不记录其中实际从者。助战概念礼装与御主礼装仍按作业要求核对。任一项不确定或不符时不得开始，超时安全停止并保留证据。
- F5.12 补刀选卡采用两层硬顺序：所有指定从者优先于空槽位中实际出现的任意从者，不区分指定从者是否被作业使用。卡色、暴击与克制只在同层内比较。指定从者内部继续适用主动换人与自动补位的接替规则。
- F5.13 当前动作仍可执行时继续原作业；行动从者、目标或所需技能／宝具／换人控件无法确认时，记录计划偏离并在当前场进入计划外自动战斗。计划偏离本身不是停止理由，只有画面或安全操作目标无法确认时才安全停止。
- F5.14 计划外自动战斗按前排从左到右、每人一至三技能使用指定从者可用技能；己方目标选择最左存活指定从者，无可用指定目标则跳过该技能；敌人目标使用当前选中敌人。技能处理完后优先使用确认可用的宝具，其中指定从者宝具优先于空槽位任意从者的宝具；没有可用宝具后，再按 F5.12 的两层顺序选择普通卡。不套用补刀 `allowNp` 与原作业固定宝具卡位；空槽位任意从者不主动释放技能。
- F5.15 进入计划外自动战斗时发出一次非阻塞提示，说明原因并明确“仅当前场自动、下一场恢复作业”；提示不暂停执行、不要求确认，运行状态与事件记录持续保留。下一场恢复原始作业与初始编队状态。
- F5.16 从者因自我退场或被敌人击倒而离场后，执行器只按画面确认更新场上从者与候补补位。指定从者补入时接替离场者的指定从者内部位置；空槽位任意从者补入时仍排在所有指定从者之后。毅力导致未退场时保持原状态，不为预期动作提前改写场上状态。

异常弹窗恢复只走下表中的明确路径；未列情况一律安全停止并保存证据，不试探按钮。

| 覆盖层 | 允许恢复的画面证据 | 动作 |
| --- | --- | --- |
| `friend_request` | 已识别的好友申请覆盖层与「结束」控件 | 点「结束」后重新识别；无控件则超时停止 |
| `support_party_confirm`、`master_equipment` | 已识别的误开页面与关闭控件 | 点「关闭」后重新识别；无控件则超时停止 |
| `repeat_dialog` | 已进入结算流程，基页为 `battle / drops / unknown` | 按剩余场数处理；等待下一页期间不重复点击 |
| `master_skills` | 当前动作由执行器打开 | 执行御主技能或换人；非执行器打开则停止 |
| `order_change`、令咒覆盖层 | 对应当前作业动作 | 按作业执行；无对应动作则停止 |
| 其他覆盖层 | 无通用恢复路径 | 安全停止 |

### F6 运行监控与控制

- F6.1 运行面板显示真实状态：当前面、回合、正在执行的动作、耗时。
- F6.2 停止按钮立即生效，停止后设备上不再有点击；不提供暂停/继续。
- F6.3 同一时间只允许一个运行中的作业。
- F6.4 执行器异常退出时，UI 显示原因与日志位置。
- F6.5 浏览器预览模式下运行功能明确禁用。
- F6.6 面板提供事件时间线，逐场、逐面显示进度，并区分已发送输入与后续画面确认。

### F7 运行记录与故障证据

- F7.1 每次运行生成记录：作业、设备、起止时间、耗时、结果。
- F7.2 结果区分完成、手动停止、失败。
- F7.3 每次运行有独立目录，含动作日志与失败截图。
- F7.4 历史页展示真实记录、实际通道、结果摘要、关键事件与识别统计；可打开证据目录或复制路径，重启后仍在。
- F7.5 未知画面安全停止时保存最终截图、观察结果、近期动作、运行进度、重试次数、停止原因及设备与作业信息，供后续分析返回正常流程的按钮并补回放用例；不得在未知画面上试探点击。
- F7.6 进入计划外自动战斗时必须记录触发时间、当前场／面／回合、无法执行的原动作与计划偏离原因；同类记录可在运行摘要中追溯。

### F8 安全边界（不可协商）

- F8.1 恢复道具只能在用户白名单内使用；白名单为空时 AP 恢复页只停不点。
- F8.2 圣晶石默认禁用，需用户显式勾选；清 AP 阶段不使用任何恢复道具。
- F8.3 不在未知画面上使用固定坐标回退。
- F8.4 任何时刻用户可接管，停止优先于作业进度。
- F8.5 计划偏离本身不是停止理由；当前动作仍可安全执行时继续，否则在当前场进入已告知用户的计划外自动战斗。画面、从者或操作目标无法确认时仍安全停止。

## 4. 非功能需求

- N1 **可验证**：执行器行为必须能用离线回放验证，不依赖实机。
- N2 **可回滚**：项目在版本控制下，重构期间任何一点可退回。
- N3 **可复现**：一条命令跑全部回放；新会话按文档即可上手。
- N4 **单进程桌面体验**：无本地网络服务，无端口，无鉴权。
- N5 **性能**：战斗中的识别循环不阻塞 UI；截图与图像识别的失败有超时上限，字段读取同步完成并记录耗时与缓存命中。
- N6 **可维护**：设备访问、画面识别、作业解析各只有一个实现，不在多处重复。

## 5. 发布门槛

- 全部回放通过，且覆盖"行为基线"清单中的每一条已验证行为。
- 桌面端完成一次真实两场连刷：退出码 0、两次战斗完成、连续出击时序正确、AP 不足即停。
- 打包后的桌面版能保存作业、下载资源、运行作业、查看历史。

## 6. 明确不做（本轮）

多设备并行与多开；任意副本自动导航与自动配队；iOS 与真机；云同步与账号；作业格式 v2（条件分支等新语义）；非精确 16:9 或低于 1280×720 的分辨率专门适配；实时游戏画面与识别调试视图。

## 7. 已确认的决策（2026-11-19 grill-with-docs 对齐）

1. **复用范围**：Vue 前端与 Tauri/Rust 壳（含 adb 设备封装）原样复用；只新写执行器，作业存储与资源更新归属重做。
2. **执行器**：Python 子进程，自带设备层；壳的 adb 代码只用于设备预览。
3. **产品形态**：Windows 桌面 + 安卓模拟器单机工具；未来可扩展 Web/移动/多开，本轮不预先实现。
4. **交付**：按可分发设计，分两期；先做到本机桌面版全流程可用，打包与首启体验在票据 11。
5. **区服**：国服/日服/台服，首期只交付国服；区服属于设备；图库按区服分目录缓存。
6. **连续出击**：固定场数 + 可选清 AP；恢复道具为用户白名单，默认仅青铜苹果。
7. **控制**：只做停止，不做暂停。
8. **恢复**：任意已知画面可接续。
9. **验收纪律**：执行器改动必须回放全绿；每个实机故障补回放用例；未经实机验收不标记稳定。
10. **前端信息架构（2026-11-24）**：按“准备 → 编队 → 运行 → 记录”组织工作区，准备管理环境与通道，编队管理从者、回合、场数和 AP，运行负责监控，记录负责复盘。
11. **运行配置（2026-11-24）**：编队页与启动流程共用一份持久化设置；AP 恢复按用户勾选顺序使用，勾选圣晶石时必须显式确认消耗；不在准备页重复放置场数与 AP 控件。
12. **作业编辑边界（2026-11-24）**：动作与回合按 Schema 保全，运行与否由编译和能力检查决定；普通指令卡统一使用选卡策略，旧固定卡序在导入时忽略并提示。技能追加选择（旧称二次选择）按索引执行，缺候选、索引或值不一致、旧字符串卡色在启动前拦截。
13. **运行与历史（2026-11-24）**：运行面板显示事件时间线，不做实时视频；历史详情读取真实结果与证据。
14. **通道默认（2026-11-24）**：scrcpy 默认，ADB 作为 scrcpy 启动失败时的可见回退；运行中断不换通道。内部验收状态不因此改变。
15. **空槽语义（2026-11-24）**：作业空槽位表示不限制，实际可为任意从者或为空；编队核对只核对指定从者，空槽不核对也不记录身份。指定从者与空槽任意从者采用两层选卡顺序，详见 ADR-0007。
16. **计划外自动战斗（2026-11-24）**：计划偏离不直接停止；原动作无法执行时，当前场进入与补刀不同的计划外自动战斗，非阻塞告知后继续，下一场恢复作业，详见 ADR-0008。
17. **换人与补位（2026-11-24）**：每场最多一次换人服主动换人；自我退场和被击倒都按画面确认补位，指定替补接替指定从者内部位置，空槽任意从者仍排最后。
