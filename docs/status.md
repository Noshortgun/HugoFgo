## 3. 战斗性能验收（#50）

同口径统计工具为 `scripts/battle_performance.py`，原始报告在本机 `logs/farm/20261123-001108-ticket-50/`。四次既有成功运行共 52 个相邻选卡样本，中位数 1214.209 ms；26 个攻击到首卡样本，中位数 2110.926 ms。报告逐条保留样本，不把选卡后的攻击动画或结算计入操作间隔。

scrcpy 首轮未通过：`scrcpy-2runs` 从不支持的幕间页安全停止；`scrcpy-2runs-02`、`scrcpy-2runs-03` 均在“列表更新”后确认超时。根因已定位为触摸消息误用按键类型 0；现按固定协议改用类型 2、32 字节字段，点击保持 40 ms，滑动约每 16 ms 采样。

修复后的证据在 `logs/farm/20261123-075232-scrcpy-protocol-fix/` 与 `logs/farm/20261123-075610-scrcpy-fixed-2runs/`：真实点击、滑动、助战、技能、定向技能、宝具及多个 200 ms 三卡批次均已生效。实机故障还促成攻击的一次新帧恢复、战斗控件恢复后停止跳过及跳过点移出御主技能区域。当时的固定作业曾按顺序点击并以至少 1.5 秒动作间隔推进；该技能时序已被后续统一恢复确认流程取代，以下旧运行不能作为新流程的实机验收。定向面板、攻击入口、选卡与补刀仍保留必要感知。

固定顺序版本运行 `scrcpy-2runs-fixed-sequence/` 在第三面因作业要求的娄希宝具充能不足而安全停止。2 个初始三卡批次均成功且无恢复，普通卡间隔中位数 200.621 ms；攻击到首卡中位数 2332.574 ms，超过 1000 ms 门槛。后续点击增加 40 ms 内的三次静止 MOVE，并完成一次中断战斗接续；重新完整验收时 AP 已耗尽且无可用白名单道具，以 `ap_recovery_no_allowed_item` 停止。技能输入与完整性能门槛仍未通过最终验收；2026-11-24 起产品默认通道改为 scrcpy，ADB 作为启动保底，但性能证据不变。

自动职阶验收 `scrcpy-auto-class-one/` 成功从枪阶切到狂阶并进入战斗，自身目标技能到下一技能间隔约 1 秒，攻击首次点击即进入选卡页。最终卡 2、4、5 身份均为 `null`，以 `fallback_cards_unavailable` 安全停止；卡面身份识别与完整作业验收仍需继续处理。

ADB 使用同一作业、当前开放的种火超级关卡完成两场，目录为 `adb-2runs-03/`。逐场逐面审计覆盖全部技能、定向技能、御主技能、宝具槽位与三卡，6 个初始批次均在 200 ms 下无恢复成功。ADB 选卡间隔中位数 200.776 ms、攻击到首卡中位数 1119.341 ms；这些数值只用于行为对照，不套用 scrcpy 门槛，也不能替代 scrcpy 证据。前序 `adb-2runs-02` 暴露第二次刷新后过渡空帧被误判为 `support_not_found`，已修复并加入单测与统一回放；失败目录仍保留。

## 4. 当前执行边界

### 作业与动作

- 实机执行统一由桌面 UI 和 `executor/` 提供；旧 `scripts/farm_ember.py` 已移除，`cv/` 只保留离线验证工具。
- `wave.target` 仅是作业与界面元数据。进入新面不会自动切敌，只有显式 `target` 动作才点击敌人。
- 所有从者技能与御主技能统一为：完成所需目标选择、动作后新画面最多空白加速一次、等待连续两个战斗可操作新帧后推进。无目标技能不再使用固定 1.5 秒等待；自身目标技能不会在旧可操作帧上提前加速而越过目标面板，加速后才出现目标面板时安全停止。每个技能最多加速一次，不检测冷却、NP 或实际生效，未知画面、意外弹窗和超时仍安全停止。五类技能流程及 `run-1795498348917-18264` 的 0.361 秒过早输入均有单测与离线回放；**修复后尚未实机复验，不能宣称稳定**。攻击停留 2 秒会基于新战斗帧最多恢复一次。第三张卡后的战斗跳过每秒最多一次，攻击和菜单恢复后立即停止，跳过点位于常驻控件之外；攻击、选卡和补刀流程未因本次技能改动调整，scrcpy 完整性能验收仍未通过。
- 完整确认五张普通卡和作业所需宝具后，执行器复用同一次手牌识别连续提交三卡，初始卡间间隔为 200 ms；整链后仍以新画面确认。选卡页停留 2 秒会基于新帧重新识别并最多恢复一次；若前一或两张已生效，只按新帧中的实际剩余卡补选对应后缀，不强制恢复五卡完整，也不复用旧坐标。失败即安全停止。动作日志记录批次、普通卡与宝具身份/卡序、实测卡间间隔、攻击到首卡耗时与恢复次数；实机审计复用领域编译结果核对控件、普通卡顺序和宝具顺序。该路径在 ADB 两场中完成 6/6 无恢复批次；scrcpy 已有含宝具的 200 ms 实机批次，但完整成功率与速度验收未通过；部分漏卡恢复仍只有离线证据。
- 每次运行在证据目录生成 `summary.md`，按场、面、回合和动作顺序显示作业中的从者与动作名称、可读开始时间和相对耗时。摘要分别标注已点击、画面已确认/未确认和没有独立生效确认，结尾汇总状态、停止原因、完成场数及未执行计划动作；事件缺失时只标注无法判定。原始 `events.jsonl` 与机器审计不变。`python -m executor.session.summary <运行目录> [--job <作业.json>]` 可重新生成；已为 `run-1795498348917-18264` 验证希耶尔 3 技能是“已点击、画面未确认、没有独立生效确认”，且事件文件 SHA-256 前后不变。桌面历史界面复用不在当前交付范围。
- 助战搜索会按作业自动点击所需职阶页签，支持七个常规职阶及狂阶右侧的 Extra 页签；已处于目标职阶时不重复点击。从者头像与概念礼装均使用图像匹配，助战选择不使用 OCR；所有可见候选行都参与翻找与到底判断，即使身份未知也不算空列表。切换后先向下翻找，翻到底仍无目标才刷新。`scrcpy-auto-class-one` 已从枪阶实机切到狂阶并进入战斗；当前职阶识别与直接翻找规则有人工关键帧离线证据，尚无修复后的实机复验。第二次刷新后的短暂空候选帧会等待重新识别，持续超过动作超时才以 `support_not_found` 停止。
- 队伍确认页核对三位先发从者、作业要求的助战概念礼装与御主礼装，不符或持续无法确认时以 `team_mismatch` 停止。普通再临与灵衣头像均归一到原从者 ID；梅林灵衣 `500830` 实机帧已通过开始任务回放，助战灵衣归一有构造 fixture 回归，均不视为修复后的实机验收。
- 不做通用副本导航、条件分支、自动配队或多设备并行。
- 未知页面和未列入恢复规则的弹窗不会试探点击；等待超时后停止并保留证据。

### 感知与选卡

- 真实感知可识别图库内助战从者/概念礼装；普通指令卡使用 Atlas `commands` 原图识别从者，并独立识别卡色、助战标记和卡面克制/抵抗/中立标识。
- 身份、槽位或卡色不确定的普通卡不参与补刀；可用卡不足三张时停止。
- 面、回合、NP 与指令卡暴击率使用同一帧局部数字模板识别，不再调用文字 OCR。面已有 1–3 模板，累计回合已验证 1–7，NP 与暴击率均有 0–9 模板；NP 另有暗帧变体与滑窗匹配。人工帧已验证第 1 面/第 1 回合/NP 40/100/40、暴击率 10/100/80/30/90，新增真实帧覆盖 50/60/100/40/30、40/100/70/30/40、NP 20/107/114/43/140/59/80/12/94/60，并以未参与模板制作的帧交叉验证。读取不确定时暴击率仍按 0 降级并警告；观察证据与 `result.json` 记录字段耗时、读取次数和缓存命中。克制识别失败时按中立处理并发出警告；克制三态识别与可配置排序已有真实截图离线回放，尚未实机复验。默认顺序为从者顺序 → 选卡倾向 → 克制 → 暴击率；旧作业的三项顺序原样保留，克制只作末位兜底。
- 普通卡按卡序位置逐张应用从者、卡色、暴击率和克制等规则，完全并列才选最左；宝具不参与普通卡排序，固定宝具位置只占对应卡序。人工三面回放已覆盖自动宝具、固定第二位宝具和暴击率优先。

- 宝具充能特效和连击前的短暂遮挡会进入等待，不把瞬态帧当成完整手牌，也不盲点。单帧出现两个及以上宝具区域时，必须连续两帧证据一致才参与选卡，避免绿色技能特效被误当成不存在的宝具卡2。

### 回合与接续

- 游戏“回合数”按跨面累计值处理；执行器另行维护面内回合。面或累计回合回退、跳变、一次跨多面等不确定进度会停止。
- 仅第 1 面累计第 1 回合的战斗起点直接执行规划回合；其他战斗起点因不知道当前面已执行什么，当前面只补刀，下一面恢复规划。
- 回合数字不可读但面已确认且攻击可用时仍可接续；面不可读、动画或阻挡覆盖层存在时停止。

### 弹窗与 AP 安全

- 助战刷新确认、刷新冷却和敌人状态详细面板已有识别、关闭与离线回归；修复后的实机运行已覆盖确认过渡和意外状态面板恢复。
- AP 数量确认框中的道具必须与刚选择的白名单项目一致才允许确认；空白名单、无待确认道具或道具不一致均停止。圣晶石已接入同一条确认流程，当前只有代码与离线验证，真实消耗尚未实机验收。
- 清 AP 阶段不使用任何恢复道具。
- 手动停止在动作边界生效；桌面壳最多等待终端事件 30 秒，超时才终止执行器进程树。
