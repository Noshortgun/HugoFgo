# 当前状态

更新于 2026-11-23。本页是当前能力与验收证据的权威来源，不记录实施过程；历史见 [HANDOFF](../HANDOFF.md)。

证据分为三层：

- **实机已验证**：在真实模拟器和游戏账号上按所列场景运行通过。
- **代码与离线验证**：实现存在，并有单测、脚本化场景或真实截图回放；不等于其他实机场景稳定。
- **未交付 / 未验收**：明确缺少实现或相应证据。

## 3. 战斗性能验收（#50）

同口径统计工具为 `scripts/battle_performance.py`，原始报告在本机 `logs/farm/20261123-001108-ticket-50/`。四次既有成功运行共 52 个相邻选卡样本，中位数 1214.209 ms；26 个攻击到首卡样本，中位数 2110.926 ms。报告逐条保留样本，不把选卡后的攻击动画或结算计入操作间隔。

scrcpy 本次未通过验收：`scrcpy-2runs` 从不支持的幕间页安全停止；`scrcpy-2runs-02`、`scrcpy-2runs-03` 均在“列表更新”后确认超时。受控诊断中持续视频与服务端按键注入可用，但触摸/滑动未改变游戏画面，50 ms 按下保持实验也无效。没有进入选卡阶段，因此 200 ms 三卡成功率、450/1000 ms 门槛均无有效实测样本，未开展 250/300 ms 调参。三个目录的事件、结果与最终帧全部保留；默认通道保持 adb。

ADB 使用同一作业、当前开放的种火超级关卡完成两场，目录为 `adb-2runs-03/`。逐场逐面审计覆盖全部技能、定向技能、御主技能、宝具槽位与三卡，6 个初始批次均在 200 ms 下无恢复成功。ADB 选卡间隔中位数 200.776 ms、攻击到首卡中位数 1119.341 ms；这些数值只用于行为对照，不套用 scrcpy 门槛，也不能替代 scrcpy 证据。前序 `adb-2runs-02` 暴露第二次刷新后过渡空帧被误判为 `support_not_found`，已修复并加入单测与统一回放；失败目录仍保留。

## 4. 当前执行边界

### 作业与动作

- 实机执行统一由桌面 UI 和 `executor/` 提供；旧 `scripts/farm_ember.py` 已移除，`cv/` 只保留离线验证工具。
- `wave.target` 仅是作业与界面元数据。进入新面不会自动切敌，只有显式 `target` 动作才点击敌人。
- 战斗内技能、切敌和攻击使用可点控件的动作级确认，不再共用 0.5 秒稳定窗口；技能后主动跳过动画，定向技能保留目标面板开关证据与一次新帧恢复，第三张卡后的战斗跳过每秒最多一次。未知画面、意外弹窗、选卡页残留及攻击/战斗菜单未恢复时不会继续点击。上述路径已由指定作业的 ADB 两场实机运行与离线回放覆盖；scrcpy 因触摸输入故障尚未完成实机验收。
- 完整确认五张普通卡和作业所需宝具后，执行器复用同一次手牌识别连续提交三卡，初始卡间间隔为 200 ms；整链后仍以新画面确认。选卡页停留 2 秒会基于新帧重新识别并最多恢复一次，失败即安全停止，不复用过期手牌。动作日志记录批次、卡序、实测卡间间隔、攻击到首卡耗时与恢复次数；该路径在 ADB 两场中完成 6/6 无恢复批次；scrcpy 尚未进入选卡阶段，没有实机速度验收结论。
- 助战列表需要预先筛选到作业所需职阶；执行器不会自动切换职阶页签。第二次刷新后的短暂空候选帧会等待重新识别，持续超过动作超时才以 `support_not_found` 停止。
- 不做通用副本导航、条件分支、自动配队或多设备并行。
- 未知页面和未列入恢复规则的弹窗不会试探点击；等待超时后停止并保留证据。

### 感知与选卡

- 真实感知可识别图库内助战从者/概念礼装；普通指令卡使用 Atlas `commands` 原图识别从者，并独立识别卡色和助战标记。
- 身份、槽位或卡色不确定的普通卡不参与补刀；可用卡不足三张时停止。
- 真实帧尚未输出指令卡暴击率和克制/抵抗：缺暴击率按 0、缺克制按中立处理并发出警告。克制三态识别与可配置排序由 [#44](https://github.com/Noshortgun/HugoFgo/issues/44) 跟踪。
- 宝具卡不识别卡面身份，只把 `np_slot:A/B/C` 的区域中心 x=420/635/855 映射到当前先发左/中/右槽位。左位和中位有实机点击证据；右位目前只有脚本与离线证据。区域歧义或无法唯一映射时停止。
- 宝具充能特效和连击前的短暂遮挡会进入等待，不把瞬态帧当成完整手牌，也不盲点。

### 回合与接续

- 游戏“回合数”按跨面累计值处理；执行器另行维护面内回合。面或累计回合回退、跳变、一次跨多面等不确定进度会停止。
- 仅第 1 面累计第 1 回合的战斗起点直接执行规划回合；其他战斗起点因不知道当前面已执行什么，当前面只补刀，下一面恢复规划。
- 回合 OCR 不可读但面已确认且攻击可用时仍可接续；面不可读、动画或阻挡覆盖层存在时停止。

### 弹窗与 AP 安全

- 助战刷新确认、刷新冷却和敌人状态详细面板已有识别、关闭与离线回归；修复后的实机运行已覆盖确认过渡和意外状态面板恢复。
- AP 数量确认框中的道具必须与刚选择的白名单项目一致才允许确认；空白名单、无待确认道具或道具不一致均停止。圣晶石确认路径仍保持拒绝。
- 清 AP 阶段不使用任何恢复道具。
- 手动停止在动作边界生效；桌面壳最多等待终端事件 30 秒，超时才终止执行器进程树。
