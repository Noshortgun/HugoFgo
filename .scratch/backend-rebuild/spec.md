# Spec: HugoFgo 后端重构 —— 统一执行器并接入桌面端

> 本文是重构票据的原始规格快照。当前产品需求以 `docs/requirements.md` 为准，当前实现状态以 `docs/status.md` 为准。

Status: ready-for-agent

汇总版本（2026-11-19 `/to-spec` 汇总）。取代本文件此前草案；最终决策已与用户逐轮确认，记录于 `docs/requirements.md` 第 7 节与 `docs/adr/0001–0004`。

## Problem Statement

我在 UI 里编好队、排好每面的技能和宝具，点"开始运行"之后什么都不会真的发生：运行面板是演示数据，桌面壳只登记状态，真正能刷本的 Python 原型和 UI 完全不通，只认一个写死的作业。作业保存与资源更新依赖开发服务器，打包后失效。我需要一个能从 UI 一键运行任意作业、过程可见、出错安全停下、支持国服并可扩展到日服台服的桌面工具。

## Solution

保留 Vue 前端与 Tauri/Rust 壳，把执行能力收敛成一个 Python 执行器子进程：读取作业 JSON，按画面状态机驱动设备，完整执行多面多回合动作，按用户白名单处理 AP 恢复，失败即安全停止并留存证据。壳负责启停执行器、转发状态事件、管理作业与资源；图库与识别配置按区服隔离。前端只把运行面板与历史页从演示数据换成真实数据。

## User Stories

### 编队与作业

1. 作为玩家，我想在 UI 里编队、选从者/概念礼装/御主礼装并切换再临，这样不用手动改 JSON。
2. 作为玩家，我想按面按回合编排技能、御主技能、换人、目标切换与攻击，这样 3T 作业能精确表达。
3. 作为玩家，我想指定宝具卡序位置，这样宝具不会放错顺序。
4. 作为玩家，我想配置全局与按面的补刀策略，这样没清场时也有可预期的行为。
5. 作为玩家，我想同名同职阶的两个从者能被区分，这样双娄希这类编队不会选错人。
6. 作为玩家，我想指定助战位并处理同名从者消歧，这样不会借错助战。
7. 作为玩家，我想保存、打开、导出作业为单个 JSON，这样能备份和分享。
8. 作为玩家，我想从 Chaldea 分享链接导入作业，这样不用重排别人分享的编队。
9. 作为玩家，我想打包后的桌面版也能保存作业，这样不必开开发服务器。
10. 作为玩家，我想作业跨区服分享，这样日服玩家也能用我的编队。

### 执行

11. 作为玩家，我想点"开始运行"后模拟器真的开始刷我选中的作业，这样不用开命令行。
12. 作为玩家，我想执行器完整执行多面多回合动作，而不是每面只执行第一回合。
13. 作为玩家，我想技能目标、御主技能目标、换人、宝具卡序严格按作业执行，这样不会放错目标。
14. 作为玩家，我想一面没清场时按补刀策略继续打，而不是卡死或乱点。
15. 作为玩家，我想执行器只按识别到的画面状态行动，识别不了就停下。
16. 作为玩家，我想每次动作后都重新识别确认，这样不会连续盲点。
17. 作为玩家，我想误入从者详情、冠位编队页或意外弹窗时执行器停止并保存截图。
18. 作为玩家，我想助战按作业搜索与选择，找不到时刷新列表，仍找不到就停止。
19. 作为玩家，我想从战斗中途、结算页或助战页启动都能接续，这样被打断后不用手动回到固定页。
20. 作为玩家，我想固定场数连刷，末场后不多点"连续出击"。
21. 作为玩家，我想场数刷完后可选继续清空剩余 AP，这样体力不浪费。
22. 作为玩家，我想 AP 不足时按我允许的方式补体力，默认只用赤铜苹果，这样不会误耗金苹果或圣晶石。
23. 作为玩家，我想清 AP 阶段不再吃任何恢复道具，这样不会陷入无限补体力的循环。
24. 作为玩家，我想看到本次运行已用多少恢复道具，这样能掌控库存消耗。
25. 作为玩家，我想我的恢复白名单选择被记住，下次启动不用重设。

### 监控与安全

26. 作为玩家，我想运行面板显示真实的面、回合、当前动作与耗时，这样能判断是否卡住。
27. 作为玩家，我想随时点"停止"立即接管，这样安全优先于进度。
28. 作为玩家，我想同一时间只能跑一个作业，避免重复操作设备。
29. 作为玩家，我想执行器异常退出时看到原因和日志位置。
30. 作为玩家，我想浏览器预览模式下运行按钮明确禁用，而不是点了没反应。

### 数据与区服

31. 作为玩家，我想图库按需下载、增量更新，不必随安装包拿几百 MB。
32. 作为玩家，我想资源文件有 SHA-256 校验，损坏能被发现和修复。
33. 作为玩家，我想图库按区服分目录缓存，切换区服不用重下。
34. 作为玩家，我想设备的区服可配置，识别配置随区服加载。
35. 作为玩家，我想未支持的区服被明确拒绝，而不是误识别后乱点。
36. 作为玩家，我想没有图库也能启动并用占位卡编队，下载后再补全。

### 记录与协作

37. 作为玩家，我想历史页是真实记录：作业、设备、区服、耗时、结果、消耗。
38. 作为玩家，我想失败记录能定位到日志与截图。
39. 作为玩家，我想记录重启后仍在。
40. 作为开发者，我想所有执行器改动都必须回放全绿才能提交。
41. 作为开发者，我想每个实机故障都补一条回放用例，防止复发。
42. 作为开发者，我想行为基线清单是验收标准，重写后不能悄悄丢能力。
43. 作为开发者，我想作业 Schema 是前后端与执行器的契约单源，避免格式理解漂移。
44. 作为开发者，我想设备访问、画面识别、作业解析各只有一个实现。
45. 作为开发者，我想项目可回滚、可复现，新会话按 README 就能上手。
46. 作为开发者，我想未经实机验收的版本不标记稳定。

## Implementation Decisions

- **复用范围**：Vue 前端与 Tauri/Rust 壳原样复用；只新写执行器，作业存储与资源更新归属重做。
- **执行器唯一**：Python 子进程是唯一实机执行入口，自带设备层（ADR-0001）。Rust 不实现战斗逻辑；壳的 adb 只用于设备预览。
- **进程缝**：启动参数（作业路径、设备、区服、运行目录、场数与恢复策略）+ stdout JSON Lines 事件 + 退出码；壳发停止信号，执行器在动作边界结束。
- **模块划分**：作业模型（parse/compile）、设备网关（frame/tap/swipe + adb 与 fake 适配器）、画面感知（read → 观察）、执行器核心（run）、运行会话（事件 + stop + 证据）、壳（命令与进程管理）、前端。
- **契约单源**：作业 JSON Schema 共享给前端与执行器；作业格式 version 1 不变，槽位引用不变。
- **画面状态机**：menu / support / team / battle / card / result / loading / unknown；每步确认，unknown 安全停止；任意已知画面可接续。
- **补刀策略**：全局与按面覆盖；同名同职阶按槽位区分。
- **恢复策略**：白名单（4 种苹果 + 圣晶石），默认仅赤铜苹果，圣晶石需显式勾选，选择持久化；清 AP 阶段禁用一切恢复道具；消耗计数入事件与历史（ADR-0004）。
- **区服维度**：区服属于设备（ADR-0003）；识别配置与图库按区服隔离；首期只实装国服，日服台服在票据 13。
- **坐标基准**：1280×720 基准，设备层换算；不支持的分辨率拒绝执行。
- **存储布局**：作业 `jobs/`；图库与清单 `data/<区服>/`；运行证据 `logs/farm/<时间戳>/`；验证素材 `captures/`；Schema `schemas/`。
- **桌面存储**：作业读写与资源任务由壳命令负责（ADR-0002）；浏览器预览只读并明确提示。
- **打包分发**：图库不随安装包；空库可启动并引导下载；资源与运行目录走应用数据路径。
- **工程治理**：项目名统一 HugoFgo；MIT 许可证；游戏立绘不随公开仓库分发，截图保留用于回放并附版权声明；README 为上手入口。

## Testing Decisions

- **唯一主测试缝：执行器接口上的回放**。假设备喂截图、记录动作，断言分类、点击坐标、停止行为、退出码；不新增平行测试体系。
- 好测试只断言外部可观察行为：点了哪里、是否停止、日志与事件内容；不断言内部调用。
- **行为基线**：`.scratch/backend-rebuild/behavior-baseline.md` 的 B01–B23 必须逐条有用例；每条标注真实截图或注入 OCR 的证据强度。
- **契约测试**：Schema 校验覆盖非法作业与不支持能力，错误定位到面与回合。
- **实机故障回归**：每次实机故障必须补截图、登记索引、补回放用例。
- **资源管线**：保留自检；SHA-256 校验与原子写入行为不变。
- **实机验收**：票据 12 由用户执行，核对退出码、日志、面板一致性与恢复策略；未通过不标稳定。
- **构建门槛**：类型检查与构建通过；回放全绿才提交。

## Out of Scope

- Web 版、移动版、多开、多账号（未来可能，本轮不实现）。
- 日服与台服交付（架构支持，首期不实装，见票据 13）。
- 暂停/继续。
- 任意副本自动导航、自动配队；关卡入口由用户手动进入。
- 作业格式 v2（条件分支、锁卡扩展语义）。
- 非精确 16:9 或低于 1280×720 的分辨率专门适配。
- iOS、真机、云同步、账号体系。
- 前端编队与编排 UI 的重新设计。
