# 49: scrcpy 持续帧与输入通道

## Parent

#49

## What to build

提供从桌面设备设置到 Python 执行器的完整 scrcpy 通道，以持续视频流和输入会话替代高频 ADB 截图与输入子进程。用户显式选择后可用同一作业运行；ADB 保留为通用回退，两种通道共用动作状态机、安全规则和统一设备接口。

## Acceptance criteria

- [ ] scrcpy 通道实现统一帧、点击、滑动和设备信息接口；感知与执行器无需按通道复制动作决策。
- [ ] 持续解码并读取最新帧，帧身份、新鲜度、尺寸和会话归属可校验；不得把旧帧当作新动作确认。
- [ ] 输入绑定同一设备与流会话，坐标继续遵守现有 1280×720 基准和受支持分辨率约束。
- [ ] 桌面端可显式选择 scrcpy，设置能传递到执行器；首版不改变默认通道，不把通道字段写入作业 Schema。
- [ ] 启动失败时给出明确提示，可按用户确认的回退策略使用 ADB；不得静默回退。
- [ ] 运行中视频流、解码或控制中断时在动作边界安全停止并保存证据，不自动跨通道续跑。
- [ ] ADB、现有 LDPlayer 原始帧和 fake 通道行为保持兼容；高性能能力不宣称适用于未验证的平台或模拟器。
- [ ] 固定版本的服务端与必要资源有明确分发、校验和缺失诊断，开发版与 Windows 打包路径均可加载。
- [ ] 设备自测覆盖启动、连续取帧、输入、资源缺失、启动失败、取帧失败、输入失败和运行中断；统一回放保持通过。
- [ ] 完成一次真实设备上的通道级冒烟，证明取帧和输入可用；完整战斗性能与默认启用由后续验收票决定。
