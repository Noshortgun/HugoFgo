# 62: 统一技能动画加速与战斗恢复确认

Source: 2026-11-24 实机运行 `run-1795498348917-18264` 及用户确认的技能流程。希耶尔 2 技能到 3 技能的真实输入间隔只有 0.361 秒，3 技能未在游戏内发动；无目标从者技能随后仍直接推进，且没有空白加速。

## What to build

将所有从者技能和御主技能统一为同一动作流程：点击技能；需要目标时先完成目标选择；等待动作后的新画面；点击一次空白区域加速；等待战斗恢复可操作后，才推进下一动作。不得再让无目标技能只等待固定时间后直接推进。

## Acceptance criteria

- [ ] 从者自身目标、指定己方目标、无目标技能，以及御主指定目标、无目标技能，全部覆盖动作后一次空白加速。
- [ ] 目标选择必须先于空白加速；没有目标面板的技能不得点击从者目标。
- [ ] 所有技能都等待战斗恢复可操作后才推进，不保留无目标技能专属的固定 1.5 秒等待。
- [ ] 防止动作后的首帧尚未反映游戏状态就被误判为恢复；真实输入间隔按输入完成时间核对，本次 0.361 秒过早点击必须有回归。
- [ ] 每个技能最多空白加速一次，不连续盲点，不打开战斗菜单。
- [ ] 不新增技能冷却或 NP 识别，不宣称已经确认技能实际生效；未知画面、超时和意外弹窗仍安全停止。
- [ ] 覆盖五类技能流程及本次实机时间证据，并同步 `cv/replay.py` 离线回放。
- [ ] 当前能力与架构文档同步更新，实机复验前不得宣称稳定。
- [ ] `npm run replay` 与 `npm run verify` 全绿。

## Blocked by

None (can start immediately)

## Out of scope

- 不修改作业格式或技能目标配置。
- 不新增技能效果、冷却或 NP 状态识别。
- 不把固定时间等待当作技能动画结束证明。
- 不改变攻击、选卡和补刀流程。
