# 59: 空槽位不限制、两层选卡与一次性编队核对

**Status:** ready-for-agent
**Blocked by:** None

## Context

用户确认部分作业只需要使用一至两名从者，但游戏仍要求至少三名实际从者。过去的规格把作业空槽位理解成“游戏内必须为空”，并要求前三槽完整，既会拒绝有效作业，也无法表达“这里放谁都行”。

当前实现另有几处不一致：

- 前端把空成员显示为“空位”，导入时省略槽位会继承编辑器当前从者。
- 前端按“前三个非空成员”压缩前排，执行器固定以物理槽位 `[0,1,2]` 为先发。
- 导入会把指向空槽位的动作、换人或目标静默删除或降级。
- 队伍核对只核对三位先发，且没有处理空槽。
- 未使用的指定从者与空槽中实际从者在选卡顺序上没有统一规则。

空槽位语义见 ADR-0007，已在需求 F1.8、F1.9、F5.11、F5.12 中确认。

## Goal

作业空槽位明确表示“不限制”，编队只在点击战斗后核对一次指定从者，补刀按“指定从者优先于空槽实际从者”的两层顺序执行。

## Constraints

- 不新增“任意从者”字段，不改变作业 version 1 的基本结构。
- 不要求前三槽在作业中完整；游戏内至少三名从者由游戏本身约束。
- 空槽位不能承载技能、宝具、换人、己方目标、宝具卡序、固定普通卡或从者优先级引用。
- 敌方目标、`enemyCount` 和敌人存活判断保持原样。
- 空槽位不核对、不记录实际从者身份，也不参与主动换人。
- 不改六槽界面视觉布局，不实现任意助战。
- 现有非空编队、显式动作和补刀行为不得回退。

## Implementation notes

- 文件语义：`name: ""`、纯空白名称和省略槽位都归一为空槽位；导出写全 0–5；导入不得继承当前编辑器里的从者。
- 前端：保留现有 `empty` 运行态即可，不新增“任意从者”选项；空槽不得被压缩出前排，也不得进入技能、宝具、换人、目标或从者优先级候选。
- 清空从者时同时清除该槽位的概念礼装、助战等专属字段。引用该槽位的旧动作、目标、宝具卡序和从者顺序保留，显示行内诊断并禁止战斗；修复后可重新启动。
- 导入：不得静默删除空槽引用的换人、目标、宝具卡序或动作；Schema 允许的数据应保留到用户修复。
- 编译器：移除任何“前三槽必须有指定从者”的要求；保留重复槽位及显式空槽引用检查。`skill` 与宝具 `attack` 必须有有效 `memberSlot`；`playerTargetSlot` 仅在出现时校验。
- 编队核对：每次运行只在用户点击战斗后执行一次，覆盖全部指定槽位（含指定候补）；空槽跳过，不记录实际身份。助战概念礼装与御主礼装继续按作业核对。连续出击的后续战斗不重复核对。
- 补刀选卡：所有指定从者（无论是否被作业使用）优先于空槽实际从者；卡色、暴击、克制和 `strategyOrder` 只在同层内比较。指定从者内部沿用第 57 票的接替规则。
- 空槽实际从者的普通卡可在身份未知时按卡色进入最低层；宝具只在允许补刀宝具时使用，轮到该从者时宝具优先于其普通卡，但不越过指定从者层。
- 计划外自动战斗、退场补位和前端退场预览不在本票范围，见第 57、64 票。

## Steps

1. 统一空槽位的导入、导出与清空字段归一化。
2. 修正前端与编译器的槽位存在性规则，保留非法引用并显示诊断。
3. 实现一次性编队核对，覆盖指定从者并跳过空槽。
4. 实现两层普通卡与自动宝具规则，补单测和回放。
5. 补充作业往返、导入保留与执行器回归测试。

## Acceptance criteria

- [ ] 作业可省略任意槽位或写空名；导入归一为空槽位，不继承编辑器当前从者；导出写全六槽。
- [ ] 空槽位在前排或后排都允许，不因空槽数量拒绝启动。
- [ ] 技能、宝具、换人、己方目标、宝具卡序、普通卡与从者优先级引用空槽时启动前拒绝并定位。
- [ ] 含上述引用的旧作业可打开修复，原动作与目标不丢失；修复前禁止战斗。
- [ ] 清空从者同时清除该槽位的礼装与助战要求。
- [ ] 每次运行只在点击战斗后核对一次编队；覆盖指定从者及其候补，空槽跳过且不记录实际身份。
- [ ] 补刀采用“指定从者 ＞ 空槽实际从者”的硬两层；卡色等同层条件不能跨层。
- [ ] 空槽实际从者不能主动放技能；其普通卡和受开关控制的宝具可参与补刀。
- [ ] `npm run verify` 全绿。
