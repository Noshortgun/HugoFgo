# 13: 日服与台服支持（后续阶段）

**Status:** needs-triage
**Blocked by:** 12（国服实机验收）

## Context

架构已把区服作为设备属性（ADR-0003），09 提供按区服的数据目录，05/07 的识别配置首期只实装国服。日服与台服的文字、OCR 语言与部分界面素材不同，不能只改配置就宣称支持。

## Goal

日服与台服设备分别完成图库下载、识别配置、回放与实机验收；未支持的区服在 UI 与执行器中明确拒绝运行。

## Constraints

- 不改作业格式；作业继续跨区服分享。
- 每个区服独立图库、清单与识别配置。
- 没有该区服素材与配置时必须报"未支持"，不得按国服规则误识别。
- 每个区服都需要自己的实机验收，不能沿用国服结果。

## Implementation notes

按区服分别完成：

- 图库：Atlas Academy 对应区服的元数据与素材，校验通过。
- 识别配置：OCR 语言、锚点文案、模板、区域限制；放在对应区服配置中。
- 素材：采集助战、队伍确认、战斗、结算、AP 恢复等关键画面，登记索引。
- 回放：行为基线中适用的条目在该区服有用例。
- UI：设备区服选择、未支持提示、资源下载按区服进行。

需要用户配合采集日服/台服真实画面；agent 不伪造素材。

## Steps

1. 先选一个区服（建议日服）采集关键画面与恢复页。
2. 实现该区服识别配置并通过离线回放。
3. 下载并校验该区服图库。
4. 实机验收该区服。
5. 台服重复以上步骤。
6. 更新 README 的支持矩阵。

- [ ] 日服与台服图库可独立下载与校验。
- [ ] 每个区服有独立识别配置，缺失时明确拒绝。
- [ ] 关键画面素材已采集并入库。
- [ ] 每个区服回放覆盖适用的行为基线条目。
- [ ] 日服、台服分别通过实机验收。
- [ ] README 支持矩阵更新。
- [ ] 未支持区服无法直接开跑。
