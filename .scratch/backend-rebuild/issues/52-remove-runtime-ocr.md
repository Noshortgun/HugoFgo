# 52: 移除执行器 OCR，改用图像数字识别

**Status:** ready-for-human

Blocked by: #55

## What to build

弃用执行器中全部 OCR 调用。面数、回合数和指令卡暴击率改为同一帧上的图像数字识别；助战、队伍、控件和弹窗继续只使用图像证据。

当前 NP、AP 和敌人数量字段不参与实机执行，不为它们保留 OCR 后门。若后续确实需要这些字段，必须另行设计图像识别并补验证。

## Acceptance criteria

- [ ] `executor/` 运行路径不再调用 RapidOCR 或其他文字 OCR；`read()` 与 `read_fields()` 均不得启动 OCR worker。
- [ ] 面数、回合、暴击率使用同一帧的局部图像与数字模板，保持帧绑定和字段状态；不拼接不同帧的结果。
- [ ] 人工帧 `manual-w1-t1-after-s3-07.png` 正确确认第 1 面、第 1 回合、NP 40/100/40，且不调用 OCR。
- [ ] 人工帧 `manual-w2-t1-cards-14.png` 正确确认暴击率 10/100/80/30/90，普通卡顺序仍为卡4→宝具→卡1。
- [ ] 克制策略、固定宝具位置、未知助战候选行、队伍三项核对和完整人工三面回放不回归。
- [ ] 记录图像字段识别耗时与缓存命中；不再出现因 OCR 队列或超时造成的 10 秒选卡等待。
- [ ] `npm run verify` 全绿；实机完成一场并逐面审计，分别报告完成、性能和剩余问题，不把离线通过写成稳定。

## Out of scope

- 不重新引入助战名称、宝具名称、技能名称或宝具等级 OCR。
- 不为未参与执行的 NP、AP、敌人数量字段新增识别功能。
- 不删除测试或降低 CI 门槛来掩盖失败。
