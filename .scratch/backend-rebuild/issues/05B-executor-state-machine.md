# 05B: 执行器状态机

## Parent

#5

## What to build

交付执行器核心：消费 #4 的 `ExecutionPlan` 与 05A 的 `Observation`（基页、变体、覆盖层、控件与可操作性），通过 #3 的 `Device` 接口推进助战选择、队伍确认、战斗、选卡、结算，并输出事件与安全停止结果。

本票不负责真实图像识别，也不搭建完整截图回放；测试使用脚本化 `Observation` 与 `FakeDevice`。补刀策略细节与 AP 恢复白名单仍分别留给 #6、#7。

## Acceptance criteria

- [ ] `run(plan, device, perception, events)` 能按基页与覆盖层推进助战、队伍、战斗、选卡、结算，不从固定线性路径盲跑。
- [ ] 每次动作前检查可操作性，并要求同一可行动观察连续稳定；原型使用 0.5 秒，正式阈值由实机标定。首次原型在队伍过渡动画中过早点击并安全停止，该故障必须有回归用例。
- [ ] 每个动作后重新截图识别；未知画面等待重试，超限后安全停止；loading 不点击。
- [ ] 第三张指令卡提交后立即停止本轮输入并等待攻击结束，不寻找不存在的确认攻击按钮，不因残留战斗元素继续选卡。
- [ ] 从者详情/意外冠位页等误开界面关闭返回；AP 恢复页按 07 策略处理（默认青铜苹果），白名单为空才停止；未知画面安全停止并保存证据；从战斗中途、结算页、助战页可接续。
- [ ] 宝具卡序读取 `npPositions`；连续出击只在弹窗出现后点击，末场不点。
- [ ] 换人按作业执行：第三面从者技能全部放完后「奥伯龙 → 玛修」，再继续选卡；不使用御主二技能。
- [ ] 事件流包含状态、面、回合、当前动作与停止原因，可被壳转发。
- [ ] 使用脚本化 `Observation` 与 `FakeDevice` 验证动作/事件/停止顺序；既有回放保持 36/36。
