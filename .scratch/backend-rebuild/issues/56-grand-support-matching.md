# 56: 冠位助战与三格冠位礼装识别

**Status:** ready-for-human

Source: 2026-11-24 编队能力审计；2026-11-28 与用户重新确认完整筛选规则。

## What to build

交付冠位助战的三格礼装编辑、作业保存、列表识别与严格筛选，并允许未强制冠位的作业选择符合条件的冠位助战。

当前问题：

- `SupportCandidate` 虽已有 `grand / grand_ce / grand_ce_ids`，感知层创建候选时没有填充，严格冠位条件仍无法生效。
- 编辑器把槽位 2 当成普通单选礼装，但礼装 ID 无法区分牵绊礼装原本效果与 NP50%。
- 槽位 1、3 只能保存单个礼装，不能表达多个可选礼装。
- 当前布尔匹配不能区分“身份未识别”和“画面不可读”。
- 每次助战搜索最多更新两次，不符合用户要求的五十次上限。

### 三槽与多选规则

- 三格礼装从上到下依次是自由礼装、牵绊礼装、增加系礼装，对应现有 `top / middle / bottom`。
- 槽位 1、3 在编辑器中支持多选；实际礼装属于所选候选集之一即可。候选集去重，空候选集表示该槽位不限，不表示必须为空。
- 不同槽位之间必须全部满足，不增加跨槽位的礼装组合绑定。
- 槽位 2 的用户条件只有“不限 / 牵绊礼装原本效果 / 牵绊礼装 NP50%”。实际状态为未装备、原本效果、NP50%；NP50% 是同一牵绊礼装的替换效果，不是任意 NP 礼装。
- 关闭“必须为冠位”时清除三槽和牵绊效果条件，避免隐藏条件继续筛选。

### 作业格式与兼容

- `grandCe.top/bottom` 与 `grandCeIds.top/bottom` 接受单值或数组；旧单值按单元素候选集处理，新多选保存数组。
- 同一礼装条件有 ID 时以 ID 匹配，名称用于显示；无 ID 时才按名称精确匹配。
- 新增可选 `grandBondEffect: "original" | "np50"`，缺省表示槽位 2 不限。新作业不再用 `grandCe.middle/grandCeIds.middle` 猜测效果模式。
- 旧作业或当前 Chaldea 导入只有牵绊礼装 ID、没有效果模式时，解释为“必须装备该牵绊礼装，原本效果或 NP50% 均可”，不得猜测为原本效果，也不得静默放宽为未装备。
- 严格冠位旧作业只有普通 `ce/ceId` 而没有槽位 1 条件时，将其作为槽位 1 的兼容来源；同时存在且冲突时拒绝执行并给出诊断。

### 选择与搜索规则

- `grandRequired=true` 时，必须确认候选为冠位助战，并满足全部已配置的从者、礼装和牵绊效果条件；不得降级选择普通助战。
- `grandRequired=false` 表示不强制冠位，不排除冠位。普通助战与冠位助战均按列表顺序参与，不额外优先任何一类。
- 普通礼装条件对普通助战核对普通概念礼装，对冠位助战核对槽位 1；冠位助战的槽位 2、3 不影响未强制冠位的作业。
- 未强制冠位且没有礼装条件时，不要求识别冠位标记。有礼装条件但无法确认应采用哪种礼装布局时，不点击该候选。
- 普通助战、任意助战和冠位助战每次选择均最多更新列表 50 次；找到合格候选提前结束，下一场重新计数。50 次后仍无合格候选，以 `support_not_found` 结束，不无限刷新。

### 看不清与认不得必须分开

- **身份未识别（认不得）**：画面清晰稳定，但所需冠位标记、礼装或牵绊效果无法匹配已知身份。不选择该候选，继续翻找和更新，不因此单独停止；搜索耗尽后按 `support_not_found` 结束。
- **已确认不符合**：候选身份或礼装与要求不同，跳过并继续搜索。
- **画面不可读（看不清）**：模糊、遮挡、转场或关键区域缺失，无法形成可靠证据。先等待重新读取；持续不可读才安全停止，给出独立的画面/冠位信息不可读原因，不得报告成 `support_not_found`。
- 完全任意助战仍可选择第一个稳定、可操作的候选，不要求先认出从者身份。

## Acceptance criteria

- [ ] 编辑器支持槽位 1、3 多选和槽位 2 的三种条件；关闭强制冠位会清除冠位专属条件。
- [ ] 作业 Schema、导入导出和旧单值兼容符合上述规则；旧牵绊礼装 ID 不会被误当成原本效果或 NP50%。
- [ ] 感知按每个候选行读取冠位标记、三格礼装和牵绊效果模式，不能用页面整体出现冠位标记替代逐行判断。
- [ ] 槽位 1、3 的候选集内任一礼装即可匹配，不同槽位必须全部满足；错误礼装、普通候选和缺条件候选不会被严格冠位作业误选。
- [ ] 未强制冠位的作业可选择满足从者与第一槽礼装条件的冠位助战，不额外优先或排除冠位。
- [ ] 清晰稳定但身份未识别的候选只跳过、不单独停止；持续画面不可读才以独立原因安全停止。
- [ ] 每次助战选择最多更新 50 次，三类助战统一适用，下一场重新计数；耗尽后以 `support_not_found` 结束。
- [ ] 真实助战列表截图回放覆盖正确候选、多选匹配、普通候选排除、牵绊原效果/NP50%、未强制冠位接受冠位候选、身份未识别继续搜索和持续画面不可读停止；不用构造图冒充真实截图证据。
- [ ] 同步 `cv/replay.py`、当前能力、作业格式与架构文档；实机复验前只标记“代码与离线验证”，不得宣称稳定。
- [ ] `npm run replay` 与 `npm run verify` 全绿。
