# 58: 任意助战选择与任意从者统一规则

**Status:** ready-for-agent
**Blocked by:** None

## Context

2026-11-24 编队能力审计发现，前端允许不指定助战从者，也允许同时指定概念礼装，但执行器只在 `supportRequired=true` 时建立助战条件，导致“从者不限、礼装指定”在选择阶段被忽略，队伍页却可能继续核对礼装。

2026-11-28 与用户重新讨论并确认：任意助战只影响助战选择，不记录或绑定实际从者 ID、职阶和礼装身份。实际选中的助战进入编队后，与自有空槽位中的实际从者统一按任意从者处理，不再设计任意助战专用战斗规则。

当前还需要修正以下不一致：

- 任意助战可能残留旧的从者身份字段；导出省略 `supportRequired=false`、导入又把缺省值当成 `true`，保存后再次打开可能变回指定助战。
- 空槽位目前不能参与主动换人或作为己方技能目标；已确认应改为按槽位允许这两类操作。
- 自动选卡允许稳定未知卡作为任意从者卡，可能掩盖指定从者识别失败；需要牌组级告警，但不增加选卡门槛或等待。
- 希耶尔锁卡会改变正常发牌，不能把锁卡期间其他从者不出卡误报为识别故障。

领域语义见 ADR-0007（2026-11-28 修订）、术语表与需求 F1.2、F1.9、F1.13、F5.6、F5.11、F5.12、F5.17。

## Goal

统一任意助战与任意从者语义：选择阶段只按显式条件选助战，编队只核对显式条件，战斗阶段任意从者可以按槽位换人和接收己方技能；自动选卡保持现有多帧确认与两层顺序，另用普通牌组和锁卡专用规则发现识别问题。

## Constraints

- 不记录、保存或绑定任意助战实际选中的从者 ID、职阶或礼装身份。
- 任意助战的概念礼装条件独立；不新增独立职阶条件。
- 任意从者可以按原始槽位换上、换下，也可以作为指定从者技能的己方目标；目标位置必须由画面确认实际有人，否则按计划偏离处理。
- 任意从者不能承担固定技能、固定宝具、固定普通卡、宝具卡序或从者优先级；这些非法引用保留并标错，修复前禁止启动。
- 非固定卡序的自动选卡不为任意从者增加正面身份证据门槛；卡色与可操作性稳定后，身份未知卡可以参与。
- 固定卡序仍必须确认指定从者身份，未知卡不得替代。
- 牌组跟踪只产生非阻塞警告，不停止刷本，不保证每次自动选卡的从者优先级完全正确。
- 冠位助战仍由票据 56 处理；本票只覆盖普通助战。
- 不改变现有指定助战的选择、搜索、刷新次数和编队核对规则。

## Implementation notes

### 1. 作业与编队归一化

- `support=true` 且 `supportRequired=false` 表示任意助战；导出显式写 `false`，不得依赖缺省值。
- 切换为任意助战时清除旧的 `name`、`svtId`、`npId`、`role`、`limitCount` 等从者身份字段，保留独立的 `ce`、`ceId` 条件。
- 导入任意助战不得因从者名为空而变成普通空位、丢失礼装或恢复旧身份；任意助战保存、导入、再次导出后语义不变。
- 编队最多一个助战槽；导入出现两个或更多助战槽时启动前拒绝并指出槽位。
- 编译器允许空槽位的主动换人与己方目标引用，继续拒绝固定技能、宝具、卡序和从者优先级引用；不得静默删除旧动作。

### 2. 助战选择与编队核对

- 从者和礼装都不限时，选择当前列表第一个稳定、可操作的候选，不要求认出从者，不为了寻找特定身份额外翻找。
- 指定礼装时只按礼装筛选；从者身份未知不妨碍选择，礼装不确定的候选不算匹配；当前页没有匹配项时沿用现有向下翻找、到底刷新规则，达到上限后以 `support_not_found` 停止。
- 画面或候选行持续不稳定时安全停止；连刷的每场重新选择，不继承上一场实际身份。
- 编队核对只检查作业显式条件：任意助战跳过从者身份，指定礼装时按实际助战槽核对礼装，完全任意时两项都跳过。
- 不将识别到的实际助战身份写回作业、编队计划或后续场次。

### 3. 任意从者战斗规则

- 任意助战实际选中后与自有空槽位实际从者使用同一套槽位和战斗规则。
- 主动换人只依赖原始槽位、当前前后排位置和可操作的换人控件，不要求任意从者身份。
- 指定从者技能可以以任意从者为己方目标；目标位置无人或无法确认时按现有计划偏离处理，不盲点。
- 任意从者的普通卡与宝具只能由运行时自动选择；宝具按左／中／右固定位置归属，受自动宝具开关控制。
- 自动选卡继续使用多帧确认，所有指定从者优先于任意从者，卡色、克制与暴击只在同层比较；助战不享有额外优先级。

### 4. 牌组与锁卡告警

- 普通阶段按同一完整十五卡牌组周期累计三名前排的指令卡；检查每个在场指定从者的出现次数是否为五，以及是否存在无法解释的未知卡。
- 只有牌组周期和前排变化历史完整时才作确定告警；换面、重洗、换人、退场补位或漏看手牌后结束当前统计段，证据不完整不得误报。
- 在当前场结束或完整牌组结束时发出非阻塞警告，写入事件与中文摘要；警告不改变选卡结果，也不停止后续场次。
- 从 Atlas 技能效果中的 `donotSelectCommandcard` 与 `cardReset` 识别锁卡技能，不按从者名称或技能编号硬编码。
- 锁卡技能必须经过现有冷却确认才算生效；随后等待重抽的新手牌稳定，校验该手牌应全部属于锁定从者。希耶尔“原理血戒 B”当前为一次、一回合，只校验重抽后的下一手。
- 锁卡校验中，持续未知卡告警为“锁定从者卡识别不稳定”，稳定出现其他从者告警为“锁卡状态与手牌识别不一致”；其他指定从者不出卡属于正常。
- 锁卡期间不套用普通十五卡统计；锁卡效果结束后重新开始普通统计。没有已确认锁卡技能或其他明确证据时，不擅自假定锁卡。

## Steps

1. 修正任意助战的前端归一化、显式导出、导入往返与多助战槽校验。
2. 按礼装独立条件实现任意助战选择，并按显式条件修正一次性编队核对。
3. 放开任意从者的主动换人与己方技能目标，保留其他非法引用的启动前诊断。
4. 保持自动选卡现有多帧与两层规则，增加普通牌组统计、非阻塞告警和运行摘要。
5. 基于 Atlas 技能效果与冷却确认实现锁卡下一手校验，覆盖希耶尔真实场景。
6. 补前端、编译器、执行器、作业往返与真实截图离线回放，随后单独进行实机验收。

## Acceptance criteria

- [ ] 完全任意助战选择第一个稳定、可操作的候选；从者身份未知不妨碍选择，持续不稳定时安全停止。
- [ ] 任意从者加指定礼装会按礼装搜索并沿用现有刷新上限；礼装不确定不匹配，找不到时以 `support_not_found` 停止。
- [ ] 编队核对跳过任意助战从者身份，只在作业指定礼装时按实际助战槽核对礼装。
- [ ] 全程不记录、保存或绑定实际助战身份；连刷每场重新选择。
- [ ] 任意助战清除旧从者身份字段并显式导出 `supportRequired=false`；往返后任意语义与礼装条件不变。
- [ ] 导入出现两个或更多助战槽时启动前拒绝；“任意从者加指定礼装”不误判。
- [ ] 任意从者可按槽位换上、换下，并可作为指定从者技能的己方目标；目标位置无人时不盲点。
- [ ] 任意从者的固定技能、固定宝具、固定普通卡、宝具卡序和从者优先级引用仍保留并标错，修复前禁止启动。
- [ ] 非固定卡序的自动选卡可使用经过多帧确认的身份未知任意从者卡，不增加正面身份证据门槛；固定卡序不用未知卡替代。
- [ ] 普通完整牌组出现指定从者卡数异常时产生非阻塞警告；证据不完整时不误报，警告写入事件和中文摘要。
- [ ] 希耶尔锁卡由技能效果元数据与冷却确认触发；重抽下一手五张同属希耶尔可正常通过，持续未知或出现其他从者时告警，其他从者不出卡不告警。
- [ ] 新增真实截图回放覆盖选择、编队核对、换人／技能目标、未知卡自动选择、普通牌组告警和锁卡校验；`npm run verify` 全绿。

## Out of scope

- 不实现冠位助战或冠位任意助战；见票据 56。
- 不新增独立助战职阶条件。
- 不记录或绑定实际助战身份，不新增作业版本来表达该身份。
- 不把牌组或锁卡告警变成自动选卡门槛，不为证明任意从者身份增加等待。
- 不调整指定助战的搜索、刷新和核对规则。
- 不宣称全部从者、全部特效或全部锁卡效果已经通过实机验收。
