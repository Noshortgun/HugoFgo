# 45: 文档质量与资源引用整理

## Why

当前文档的主要问题不是数量不足，而是权威内容失修：能力状态存在过期结论，用户指南偏开发环境，架构页缺少真实进程协议，资源与实机证据的分类和引用关系不清楚。直接移动或删除采集文件又会破坏回放、模板再生成和本地唯一证据。

## Goal

让当前用户能看懂已验证能力、运行条件与失败处理，让开发者能仅凭文档理解本地接口和资源契约；同时建立低风险的文件引用地图，不实际清理素材。

## Scope

- 修正 `docs/status.md`、`docs/job-format.md` 的过期或冲突表述，记录 #12 限定实机证据与 #41 当前进度。
- 重整 `README.md` 与 `docs/user-guide.md`，区分安装版、源码开发版和浏览器预览。
- 扩充 `docs/architecture.md` 的真实 Tauri、CLI、stdin、事件、退出码和运行文件契约。
- 在 `docs/resources.md`、`docs/testing.md` 建立资源分类、引用关系和证据层级。
- 增加 `scripts/README.md` 与必要的本地链接、模板来源和仓库必需截图检查。
- `HANDOFF.md` 只增加历史属性说明，不改写旧条目。
- 新建 `ticket/45-docs-quality` 分支，完成后提交审阅，不自动合并。

## Out of scope

- 不移动、重命名或删除素材，不处理 Git worktree。
- 不修改当前未提交的作业和留出集采帧脚本。
- 不改变运行时代码行为，不增加 HTTP 后端。
- 不把指定种火作业验收写成通用稳定性，不把安装包构建写成安装版验收。

## Verification

- 文档中的当前状态、字段语义和接口与代码及验收记录一致。
- Markdown 本地链接、模板来源和仓库必需截图检查通过；干净 CI 不依赖本机 `logs/`。
- `npm run verify` 全绿。
- 文件整理不删除或移动任何现有素材。
