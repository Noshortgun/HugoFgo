# 50: 实机性能验收与 scrcpy 默认启用

## Parent

#49

## What to build

用同一作业、同一模拟器和同区服验证优化后的完整战斗，比较既有基线与 scrcpy 实机结果，核对动作没有缺失，并在全部安全和性能门槛通过后默认启用 scrcpy。ADB 同步验证行为一致，但不套用持续帧通道的速度门槛。

## Acceptance criteria

- [ ] 使用既定种火作业完成覆盖多面、技能、定向技能、宝具与三卡提交的 scrcpy 实机运行，保存完整事件、结果和最终画面。
- [ ] 普通选卡间隔中位数 ≤0.45 秒，攻击到首卡中位数 ≤1.0 秒；统计排除游戏动画本身，并与四次既有成功运行的同口径基线对比。
- [ ] 200 ms 初始卡间间隔的三卡提交成功率有实机证据；若漏卡，保存故障证据、补回放并评估 250/300 ms，不能隐藏失败样本。
- [ ] 逐面逐回合核对实际动作与作业计划，计划动作不得跳过；技能、目标、宝具和卡序与作业一致。
- [ ] 验证卡面未展开、提交停留、一次恢复、恢复失败、意外弹窗和通道中断的安全行为；每个实机故障新增回归用例。
- [ ] ADB 使用相同作业完成行为一致性验证，未知画面和意外弹窗仍安全停止，不要求达到 scrcpy 速度指标。
- [ ] 统一回放、执行器测试、设备自测和项目标准验证入口全部通过，实机证据与离线证据分别记录。
- [ ] 只有上述 scrcpy 门槛全部通过后才默认启用支持设备上的 scrcpy；回退与中断行为在界面和文档中明确可见。
- [ ] 更新当前能力、架构与实机验收证据；未通过的项目保持未验收，不以离线结果宣称稳定。
