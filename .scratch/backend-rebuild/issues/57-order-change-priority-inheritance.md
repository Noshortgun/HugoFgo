# 57: 每场一次主动换人、退场补位与指定从者内部接替

**Status:** ready-for-agent
**Blocked by:** 59（空槽位不限制、两层选卡与一次性编队核对）

## Context

用户确认换人服冷却很长，正常每场战斗最多主动换人一次。除此之外，阿拉什、哈贝喵等从者可能自我退场，也可能被敌人击倒，随后由候补自动补位。当前执行器只有主动换人的 `active_slots` 更新，没有替补位置、退场、毅力或自动补位模型，后续技能、目标和宝具位置可能继续引用已经离场的从者。

本票按以下已确认规则改造：

- 所有指定从者同属高层，空槽实际从者始终在低层。
- 主动换人和自动补位都只改变当前场上位置，不改变作业里的原始槽位编号。
- 上场指定从者接替离场者在指定从者内部的位置；空槽实际从者补位后仍排最后。

## Goal

每场最多一次换人服主动换人；无论主动换人、自我退场还是被敌人击倒，执行器都以画面确认结果更新场上阵容，并按接替规则继续选卡。

## Constraints

- 不新增“预期自我退场”字段，不修改作业 Schema；兼容 Chaldea 原有动作表达。
- 不根据从者 ID 或名字直接假设已经退场；毅力、未退场或画面不明时保持原状态。
- 空槽位不能被主动换人，也不能被作业动作引用。
- 计划外自动战斗的规则、弹窗与前端预览在第 64 票，本票只提供正确的当前场上状态和接替顺序。
- 不改变显式宝具卡位、普通指令卡身份或有效策略的其他字段。
- 同一场跨面保持接替结果；下一场恢复原始场上位置和从者顺序。

## Implementation notes

- 主动换人：编译器或运行前检查拒绝同一场战斗中的第二次 `orderChange`。执行器维护“原始槽位 → 当前前排／替补位置”的映射，不能继续只把 3–5 当永久替补。
- 换人确认：只有后续画面确认后才更新映射；换下者进入替补，换入者进入其场上位置。每场开始恢复初始前排与替补顺序。
- 退场补位：扩展感知或事件，确认原从者离场和实际补入者后再更新。自我退场和被敌人击倒使用同一状态更新路径。
- 接替顺序：指定从者补入时接替离场者在指定从者内部的位置；离场者不再参与当前场顺序。空槽实际从者补入时仍排所有指定从者之后，不继承指定层位置。
- 按面策略：全局和每个 `strategyByWave` 覆盖各自按自己的原始顺序应用相同接替规则，不能把某一面的自定义顺序改回全局顺序。
- 换人、退场和连续的自动补位都按当前状态继续，不累积重复项。
- 无法还原此前换人与补位历史但能确认当前战斗画面时，交给第 64 票进入计划外自动战斗；不得猜测历史后继续原计划。
- 显式 `attack`／`npPositions` 的宝具位置与身份不因优先级接替而改写。

## Steps

1. 建立当前前排、替补队列和原始槽位映射，替换固定 `[0,1,2]` / 3–5 假设。
2. 接入主动换人的一次限制和确认后交换。
3. 增加退场与自动补位确认，更新当前场上状态。
4. 把两层选卡顺序接入指定从者内部接替，并按面独立重算。
5. 补策略单测、换人／补位 Runner 测试和离线回放。

## Acceptance criteria

- [ ] 同一场战斗第二次主动换人在启动前拒绝。
- [ ] 主动换人确认后，原始槽位编号不变，程序能定位每名指定从者当前在前排或替补。
- [ ] 指定从者自我退场或被击倒后，只有画面确认补位才更新场上状态。
- [ ] 毅力或未退场时不提前移动、删除或替换原从者。
- [ ] 指定替补接替离场者在指定从者内部的位置；空槽实际从者补位后仍排最后。
- [ ] 换人与补位只改变顺序，不改变从者身份、显式宝具卡位或普通卡身份。
- [ ] 全局与按面策略各自接替；同一场跨面保持，下一场全部恢复初始状态。
- [ ] 无法还原历史但能确认战斗画面时进入第 64 票的计划外自动战斗。
- [ ] 新增策略与执行器测试、换人／补位回放，`npm run verify` 全绿。
