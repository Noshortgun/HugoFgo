# 71: 编队页拖放、助战标记与运行控制交互修复

**Status:** ready-for-agent
**Blocked by:** None

## Problem Statement

编队页目前存在一组互相放大的交互问题：卡片拖放不可用；启动前检查混合当前诊断与过期结果，警告关闭后仍会频繁重现；助战被全部移除后没有恢复入口；删除从者会把旧操作重映射到空槽，随后选择新从者又让旧操作复活；窗口尺寸变化会遮住御主礼装；运行中的编队按钮不能停止；作业库入口过小；设备选择必须离开编队页；也没有一次性清空编队与操作序列的入口。

这些问题使用户难以预测编辑结果，并可能在启动前面对已经修复的警告或与当前从者不符的操作序列。

## Solution

在不改变作业 version 1 基本结构、不修改执行器运行协议的前提下，集中修复编队页的拖放、助战、诊断、删除、运行控制和设备选择交互。

卡片拖动采用两卡整体互换。助战显示为独立、可点击和可拖动的标记，并始终保持有且仅有一个；整卡互换时助战跟随原从者，拖动助战标记时只转移助战身份。删除从者会清除其关联操作，清空编队则提供带确认的统一入口。检查警告只在保存和启动时集中展示，运行按钮可直接切换为停止，设备状态入口展开快速检测与选择，御主礼装和作业库入口完成可见性与响应式修复。

## User Stories

1. 作为编队用户，我希望拖动一张卡到另一张卡时两者整体互换，以便准确调整原始槽位顺序。
2. 作为编队用户，我希望整卡互换时从者、操作序列和助战状态保持一致，以便排序不会悄悄改变作业含义。
3. 作为编队用户，我希望编队始终有且仅有一个助战标记，以便任何状态下都知道助战位于哪个槽位。
4. 作为编队用户，我希望点击助战标记即可编辑助战条件，以便从统一入口管理指定或任意助战。
5. 作为编队用户，我希望把指定助战标记拖到另一张从者卡后，原助战变成自有从者、目标从者变成指定助战，以便只改变助战身份而不交换卡片。
6. 作为编队用户，我希望助战礼装条件随标记移动而操作序列仍归属原从者，以便筛选条件与战斗动作不会错误串联。
7. 作为编队用户，我希望指定助战标记拖到空槽后得到任意助战，以便在没有指定目标时仍保留唯一助战。
8. 作为编队用户，我希望任意助战标记拖到从者卡后得到该从者的指定助战，以便通过同一动作切换任意和指定语义。
9. 作为编队用户，我希望删除指定助战或将其切换为任意助战时清除原助战的关联操作，以便旧动作不会在新从者上复活。
10. 作为导入旧作业的用户，我希望零助战作业在导入前要求我选择一个助战槽，以便不自动丢失或替换任何从者。
11. 作为编队用户，我希望保存和启动时才集中看到检查警告，以便编辑过程中不被重复提示打扰。
12. 作为编队用户，我希望已修复的诊断立即消失、关闭的同一批警告不反复出现，以便只处理当前真实问题。
13. 作为编队用户，我希望警告与战斗按钮的禁用依据一致，以便理解为什么能够或不能启动。
14. 作为编队用户，我希望关闭从者时清除其技能、宝具、目标、换人和卡序关联，以便后续编入新从者不会继承旧动作。
15. 作为编队用户，我希望一键清空编队前看到确认，以便一次性移除所有从者与操作且不误触。
16. 作为编队用户，我希望清空后保留作业名称、御主礼装和运行设置，并在第一槽保留任意助战，以便重新开始编队而不重复配置作业级选项。
17. 作为准备启动的用户，我希望编队按钮依次显示战斗、启动中、停止和战斗，以便在当前页面控制运行。
18. 作为编队用户，我希望点击现有设备状态后即可检测并选择设备，以便不离开编队页完成启动前准备。
19. 作为使用不同窗口尺寸的用户，我希望御主礼装不被操作栏遮挡，以便始终能查看和选择它。
20. 作为作业库用户，我希望入口有足够的文字、图标和点击区域，以便快速找到并打开作业库。
21. 作为维护者，我希望旧票中被本票取代的删除与助战数量规则有明确关联，以便后续实施不会混用两套行为。

## Implementation Decisions

### 卡片与助战标记

- 保留固定六槽位。卡片拖放是两卡整体互换，不使用插入顺移；提供明确的拖动区域，避免与卡片按钮冲突。
- 整卡互换时，从者身份、会话内从者标识、操作序列、助战标记与助战筛选条件一起移动。
- 助战标记在视觉上是卡片上的独立控件，但作业仍使用现有槽位字段表达，不新增作业版本或独立助战对象。
- 点击助战标记打开助战配置；拖动标记只改变自有／助战身份，不交换从者的位置。
- 指定助战标记拖到另一张从者卡时，原从者保留在原槽并变成自有从者，目标从者变成指定助战。双方操作序列保留在各自从者上。
- 助战普通概念礼装等筛选条件随标记移动，原槽清除这些条件；冠位礼装不属于本票范围。
- 指定助战标记拖到空槽时，原从者变成自有从者，目标槽成为任意助战。
- 任意助战标记拖到从者卡时，目标从者成为指定助战，原槽成为普通空槽；拖到另一空槽时只移动任意助战及其筛选条件。
- 仅拖动助战标记不删除操作序列。整卡互换与标记拖动是两种不同操作，不得复用成同一种状态转换。
- 删除指定助战或把指定助战切换为任意助战时，在原槽保留任意助战标记，并清除原助战从者的全部关联操作。
- 编队始终有且仅有一个助战槽。零助战旧作业在导入前弹出槽位选择，选定现有从者作为助战后完成导入；取消选择则取消导入。多个助战的异常作业继续拒绝启动。
- 本规则取代票据 58、59 中“最多一个助战”和“清空助战时移除助战字段”的旧交互约束，但不改变任意助战、任意从者、编队核对和自动选卡的运行语义。

### 删除与清空

- 用户在编队页主动关闭普通从者时，删除该从者自己的技能和宝具、以它为目标的技能、涉及它的换人动作，以及宝具卡序、固定普通卡和从者优先级中的关联引用。
- 其他从者的独立动作保持原有顺序。同一槽重新选择从者时不恢复已删除操作。
- 主动删除与旧作业导入是两个不同入口：导入仍保留 Schema 允许但当前不可执行的引用并给出诊断，不借本票静默清理导入数据。
- 新增编队级“清空编队”按钮，点击后要求一次确认。
- 确认清空后，六个槽位的从者、全部回合操作、宝具卡序、选卡策略和助战筛选条件被清除；第一槽保留任意助战标记。
- 清空保留作业名称、御主礼装、刷本次数、清 AP 与 AP 恢复策略等作业级设置，不提供隐式撤销。

### 诊断、运行与设备

- 顶部检查警告在保存当前作业和点击战斗时集中展示；普通编辑不反复弹出总警告。
- 编辑发生后，当前本地诊断重新计算，上一次完整校验或执行器返回的过期诊断不得继续混入当前结果。
- 同一批警告关闭后保持稳定；诊断集合实际变化或再次点击战斗时可以重新显示。诊断消失后重置对应关闭状态。
- 战斗按钮的禁用与警告使用同一份当前阻断错误；非阻断提示不额外禁用启动，不新增一套严重级别分类。
- 编队按钮状态为“战斗 → 启动中 → 停止 → 战斗”。保存、校验和进程启动期间显示禁用的启动中；运行中复用现有停止接口，失败后恢复可操作状态。本期不增加取消启动。
- 保留并优化现有顶栏设备状态显示。在编队页点击状态后原位展开浮层，提供手动检测设备、设备列表和连接状态。
- 选择设备后更新顶栏并收起浮层，点击外部也收起。进入编队页不自动检测；截图与测试点击继续留在准备页。

### 布局与入口

- 御主礼装与操作序列、运行设置之间通过正常布局保留空间，不再依赖互相覆盖的绝对定位；在项目支持的窗口尺寸内缩放时不得遮挡。
- 作业库继续使用现有弹窗与作业存储，只增强编队页入口的文字、图标、尺寸和点击区域。

## Testing Decisions

- 测试以外部可观察行为为准：槽位内容、助战身份、操作序列、诊断可见性、按钮状态、设备浮层和布局结果，不绑定组件内部实现。
- 优先扩展现有作业往返自检这一最高纯逻辑 seam，覆盖整卡互换、助战标记转移、删除级联、清空、任意助战往返和零助战导入修复。
- 更新现有“清空从者后旧动作改挂空槽并复活”的旧断言，使其验证用户主动删除会清除关联操作；同时保留旧作业导入不静默丢动作的独立覆盖。
- 使用现有桌面运行桥和停止接口验证按钮状态，不新增执行器协议或另建运行状态模型。
- 在真实桌面窗口验收拖放、助战标记点击与拖动、设备浮层、作业库点击区域和窗口缩放；这些视觉交互不能仅靠纯函数测试宣称通过。
- 本票不改变执行器或图像识别行为，仍运行统一回放以证明没有跨层回归；未经实机验收不宣称设备连接或停止流程稳定。
- 文档与票据使用现有引用检查和 issue 漂移检查。

## Out of Scope

- 不实现或修改冠位助战、冠位礼装多选、牵绊效果或相关识别；票据 56 保持独立。
- 不新增启动过程取消、暂停／继续、触摸或键盘排序。
- 不把截图、测试点击和资源管理搬入编队页，不增加后台自动设备检测。
- 不改变作业 version 1 基本结构、任意从者运行语义、编队核对、自动选卡或执行器停止协议。
- 不自动修复多助战异常作业，不在导入时静默删除不可执行引用。
- 不因本票更新当前能力为“已交付”或“实机稳定”。

## Further Notes

本票取代票据 58、59 中与新交互直接冲突的局部规则：助战数量改为恰好一个；用户主动删除从者改为清除关联操作；删除指定助战改为原槽保留任意助战。旧票其余已经验收的任意从者、空槽位和运行语义不变。

## Acceptance Criteria

- [ ] 任意两张卡可通过明确拖动区域整体互换；不是插入顺移，从者与操作序列保持一致。
- [ ] 整卡互换时助战跟随原从者；助战标记拖动只转移身份，不与整卡互换混淆。
- [ ] 编队始终有且仅有一个助战标记，所有助战／空槽边界均按规格工作。
- [ ] 助战筛选条件随标记移动；仅拖动标记不删除双方操作序列。
- [ ] 删除指定助战或切换为任意助战会清除原助战关联操作，并在原槽保留任意助战。
- [ ] 零助战旧作业必须经用户选择槽位后才能导入，取消则不修改当前编队。
- [ ] 删除普通从者会清除全部关联动作与引用，其他动作顺序不变，新从者不会继承旧操作。
- [ ] 旧作业导入仍保留 Schema 允许的不可执行引用并给出诊断，不被主动删除规则误清理。
- [ ] 保存与启动集中显示当前警告；编辑后无过期诊断，同一批关闭后不反复出现。
- [ ] 警告与战斗按钮使用一致的阻断错误；非阻断提示不阻止启动。
- [ ] 清空编队需要确认，结果为第一槽任意助战加五个普通空槽，关联操作与策略全部清除。
- [ ] 清空保留作业名称、御主礼装、刷本次数、清 AP 和 AP 恢复策略。
- [ ] 编队按钮按“战斗／启动中／停止／战斗”切换，运行中可调用现有停止，启动失败可恢复。
- [ ] 编队页可通过现有设备状态浮层手动检测并快速选择设备，选择后与准备页共享同一选择状态。
- [ ] 支持的窗口尺寸内御主礼装不被遮挡，作业库入口清晰可见且易于点击。
- [ ] 作业往返自检、前端构建、统一回放、引用检查和完整验证通过。
- [ ] 真实桌面窗口交互验收完成；未覆盖的实机能力不作稳定性声明。
