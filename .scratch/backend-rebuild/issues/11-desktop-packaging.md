# 11: 桌面版打包与图库分发

**Status:** ready-for-agent
**Blocked by:** 08（运行桥接）、09（存储与资源迁移）

## Context

当前 `dist/` 只有少量演示资源，真实图库不入库也不随包分发；作业与资源功能在 09 后才脱离开发服务器。执行器是 Python 子进程，打包时必须能被桌面版找到。

## Goal

生成可分发的 Windows 桌面安装包；无图库也能启动并明确引导下载；作业、资源、运行、历史在打包版中全部可用。

## Constraints

- 图库不进入安装包。
- 不依赖项目源码目录、开发服务器或本机临时 Node 路径。
- Python 执行器的打包策略必须明确：随包附带运行时，或检测用户 Python 并给出可操作提示；选择后写入文档。
- 空图库不能导致白屏或静默失败。
- 打包前构建与回放全绿。

## Implementation notes

需要完成：

- `src-tauri/tauri.conf.json` 的产品名、标识符、图标与 bundle 配置核对。
- 前端资源基础路径由壳解析，不再假设开发服务器根目录。
- 作业、设置、历史、运行证据统一使用应用数据目录；开发期可保留项目目录映射。
- 首启无图库时显示引导：选择区服并下载；提供占位卡回退。
- 执行器子进程定位策略：优先随包路径，其次 `HUGOFGO_PYTHON` 与系统 Python；错误提示包含解决办法。
- 提供一条打包命令与发布说明。

如果选择随包附带 Python，需要单独记录体积与依赖打包方式；如果选择检测用户 Python，则安装说明必须列出依赖安装命令。

## Steps

1. 确定并记录 Python 执行器的分发策略。
2. 统一应用数据目录与资源路径解析。
3. 实现空图库首启引导。
4. 配置并生成 Windows 安装包。
5. 在干净目录中安装并验证四项核心功能。
6. 运行 Verification。

## Verification

```bash
npm run build
npm run replay
npm run tauri build

# 安装生成的安装包后：
# 1. 无图库能启动并看到下载引导
# 2. 下载国服资源后图鉴可用
# 3. 作业保存/打开可用
# 4. 假运行或实机运行可用，历史有记录
```

## Acceptance criteria

- [ ] 安装包可生成并可安装启动。
- [ ] 无图库启动有明确引导，不白屏。
- [ ] 图库按区服下载后立即生效。
- [ ] 打包版不请求开发服务器路径。
- [ ] 作业、资源、运行、历史均可用。
- [ ] 运行目录与资源目录不依赖项目源码位置。
- [ ] Python 执行器分发策略已写入 README。
- [ ] 构建、回放与打包命令通过。
