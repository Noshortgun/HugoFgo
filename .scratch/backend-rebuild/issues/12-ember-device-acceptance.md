# 12: 种火作业实机验收

**Status:** ready-for-human
**Blocked by:** 06（补刀策略）、08（桌面运行桥接）

## Context

行为基线清单已整理在 `.scratch/backend-rebuild/behavior-baseline.md`。旧原型曾在 `logs/farm/20261119-200229/` 完整跑通，但那是旧代码的结果，不能代替新后端验收。

本票据由用户在真实模拟器上执行，agent 负责准备环境、核对清单和归档结果。

## Goal

新后端在真实设备上完成种火作业验收，证明能力不低于旧原型，并验证 AP 恢复白名单与清 AP 行为；通过后才移除旧后端代码。

## Constraints

- 必须使用真实模拟器与真实游戏账号，不用假运行代替。
- 不为了通过验收而临时关闭安全停止。
- 任何失败都保留日志与截图，并补回放用例。
- 验收通过前不得宣称"全自动稳定版"。

## Implementation notes

前置准备：

- 模拟器 1280×720，国服，已进入种火副本助战选择页或任意已知画面。
- 选择 `jobs/娄希、娄希、奥伯龙.json` 或当前等效作业。
- 准备足够 AP；恢复白名单先只勾青铜苹果。
- 记录开始前的 AP 与苹果库存截图。

验收场景：

1. 从助战页启动两场连刷。
2. 从战斗中途启动并接续。
3. 白名单仅青铜苹果时触发 AP 恢复。
4. 白名单为空时触发 AP 恢复。
5. 开启清 AP，场数完成后继续到 AP 归零。

每个场景记录退出码、日志、最终画面、面板状态与消耗数量。

通过后清理：

- 移除 `scripts/farm_ember.py` 与旧 `cv/` 执行代码中被新执行器取代的部分。
- 保留 `captures/` 与回放用例。
- 更新 README 的运行方式与 HANDOFF。

## Steps

1. agent 核对全部回放与构建，确认可进入实机验收。
2. 用户按五个场景逐一运行，agent 协助读取日志。
3. 任何失败先补回放用例，再修复，再重跑该场景。
4. 全部通过后归档日志与截图，追加 HANDOFF。
5. 移除旧后端代码并再跑一次全量回放与构建。

## Verification

```bash
npm run replay
python -m executor.replay
npm run build

# 实机：从桌面端启动，记录每个场景的退出码与日志
```

通过标准：

- 两场连刷退出码 0，两次战斗完成，中间连续出击一次，末场不多点。
- 中途启动能接续。
- 非白名单恢复方式不被使用；空白名单时安全停止。
- 清 AP 阶段不吃道具，AP 归零完成。
- 面板状态与真实画面一致。
