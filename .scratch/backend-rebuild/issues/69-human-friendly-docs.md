# 69: 面向新读者重组项目文档

**Status:** ready-for-agent
**Blocked by:** None

## Problem Statement

现有文档混合了新手操作、架构解释、接口契约和验收证据。不了解项目的读者需要先从技术栈、术语和维护规则中自行找出使用路径，也难以把“作业、画面感知、执行器、安全停止”等概念对应到实际 FGO 刷本过程。

## Solution

将文档分成场景化导读与精确技术参考两层。项目入口先解释工具用途和一次刷本的完整流程；使用指南按准备、编队、运行和记录组织；新增工作原理，用助战选择、队伍确认、指令卡、技能确认、AP 恢复和结算画面解释模块分工。文档地图按读者目标导航，字段、接口、当前状态和术语仍由原有权威文档维护。

## User Stories

1. 作为第一次接触项目的 FGO 玩家，我希望先理解工具替我做什么，以便判断它是否适合当前需求。
2. 作为新用户，我希望按真实刷本顺序阅读操作步骤，以便完成第一次运行并找到停止原因。
3. 作为新开发者，我希望通过游戏画面理解模块职责，以便再进入接口和协议文档。
4. 作为文档维护者，我希望导读与技术参考分工明确，以便避免重复维护字段、接口和验收结论。

## Implementation Decisions

- 重写 `README.md`、`docs/README.md` 和 `docs/user-guide.md` 的读者路径，不改变产品行为。
- 新增 `docs/how-it-works.md`，按前端与壳、作业模型、画面感知、执行器核心、设备网关和运行会话组织。
- 从已入库关键帧生成六张轻度模糊、960×540 的导读图片，放入 `docs/assets/how-it-works/`；图片不构成新的实机验收证据。
- 在 `docs/resources.md` 登记文档派生图片的来源与入库规则，并同步根 README 的游戏素材用途说明。
- 保留 `docs/status.md`、`docs/requirements.md`、`docs/architecture.md` 和 `GLOSSARY.md` 的权威地位，不复制其详细契约。

## Testing Decisions

- 运行离线预检，确认分支和票据发布源一致。
- 运行文档与素材引用检查，覆盖新增图片和交叉链接。
- 在基于最新 `origin/main` 的独立工作区运行完整验证，避免当前其他施工分支的未提交修改影响结论。

## Out of Scope

- 不修改执行器、图像识别、前端或桌面壳行为。
- 不新增实机验收结论，不把导读截图作为识别或稳定性证据。
- 不携带其他分支的作业、回放、需求、架构和术语改动。

## Verification

```bash
npm run preflight -- --offline
npm run references:check
npm run verify
```

- [x] 文档地图按读者目标导航，权威文档边界保持明确。
- [x] 独立工作区的引用检查与完整验证通过。
