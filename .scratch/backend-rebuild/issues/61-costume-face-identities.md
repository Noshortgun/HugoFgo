# 61: 补齐从者灵衣头像识别资源

Source: 2026-11-24 实机运行 `run-1795492984431-30616` 及用户确认的设计。梅林使用灵衣 `500830` 时，队伍确认无法归一到梅林 `500800`，执行器因此不点击“开始任务”；手动停止前后的同类运行以 `team_mismatch` 结束。

## What to build

让现有资源更新为所有从者增量获取灵衣头像，并使助战选择与队伍确认都能把灵衣外观识别为原从者。灵衣只是同一从者的外观变体，不改变从者身份，不要求作业记录灵衣，也不改变识别失败时的安全停止策略。

## Acceptance criteria

- [ ] 资源更新覆盖所有从者已发布的灵衣头像，旧安装可通过普通增量更新补齐，识别运行时保持离线。
- [ ] 灵衣头像与原从者 ID 关联，保留已有特殊形态资源逻辑，不增加梅林特判。
- [ ] 灵衣头像纳入资源清单与 SHA-256 校验，但不作为所有区服必须非空的全局资源类别。
- [ ] 助战选择和队伍确认均能正确归一灵衣身份；梅林灵衣 `500830` 的队伍实机帧识别为梅林 `500800`，并允许通过队伍身份核对。
- [ ] 素材缺失、识别不确定或身份有歧义时仍不得点击“开始任务”或放宽助战条件。
- [ ] 两条识别链路都有自动化回归，梅林队伍实机帧进入统一回放；构造的助战 fixture 不得宣称为实机验收。
- [ ] 资源、术语与当前能力文档同步更新。
- [ ] 资源管理器自检、资源校验、统一回放及 `npm run verify` 全绿。

## Blocked by

None (can start immediately)

## Out of scope

- 不修改作业格式或要求用户指定灵衣。
- 不修改普通指令卡识别链路。
- 不降低队伍身份核对或助战条件。
- 不增加应用迁移、全局启动阻断或按作业临时联网下载。
