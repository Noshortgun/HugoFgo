# 60: 技能追加选择的执行器支持

**Status:** ready-for-human

Source: 2026-11-24 用户确认，高优先级能力缺口。前端称“技能追加选择”，旧文档和字段称“二次选择”。

## What to build

部分技能点击后还会出现追加选择界面，例如宇宙伊什塔尔切换宝具卡色。前端已经记录选项，执行器必须识别该界面、选择配置项并确认，然后继续原技能流程。

这是独立的感知与交互流程，不是普通的己方/敌方目标选择。当前启动前会拦截所有带 `secondarySelection` 的动作。

## Acceptance criteria

- [ ] 识别技能追加选择界面及其选项，不使用固定坐标盲点。
- [ ] 按作业记录选择正确选项；选项文字、图片或索引不一致时安全停止。
- [ ] 处理追加选择与后续技能目标选择的先后顺序。
- [ ] 选择确认后继续原动作，完成后才推进动作序号。
- [ ] 无法识别界面、选项或确认结果时给出独立失败原因并停止。
- [ ] 启动前能力检查只在实现并验收集成通过后取消对应拦截。
- [ ] 至少覆盖一个宝具卡色切换技能的真实截图回放和一次实机运行。
- [ ] `npm run verify` 全绿。

## Out of scope

- 不实现无配置时的自动猜测。
- 不把普通目标选择改造成追加选择。
- 不改变作业 Schema 的 `secondarySelection` 结构。
