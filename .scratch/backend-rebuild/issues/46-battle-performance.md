# 46: 自动战斗操作速度优化

## Problem Statement

当前自动战斗的操作速度明显慢于 Mash。对 4 次成功实机运行的 222 个同回合动作间隔进行统计，排除选卡后的攻击动画与结算后，攻击前动作间隔中位数为 3.521 秒，攻击到首卡为 2.111 秒，相邻选卡为 1.214 秒。

已确认主要成本来自所有点击共用的 0.5 秒稳定等待、每次点击后的重新取帧确认、默认 ADB PNG 截图，以及指令卡的重复身份识别。普通战斗帧感知约 20 ms，因此问题不是单纯的 Python 或模板识别速度。

## Solution

提供以画面证据为边界、按动作类型确认的快速战斗执行路径。正常选卡一次识别后按 200 ms 初始间隔连续提交三卡，技能和攻击主动跳过可跳过动画；新增 scrcpy 持续帧与输入通道，同时让 ADB 共用同一套动作状态机。

优化不得把未知画面、意外弹窗或身份不确定变成盲点。速度目标只作为 scrcpy 实机验收线；ADB 保持行为一致，不承诺相同速度。

## User Stories

1. 作为刷本用户，我希望技能、切敌和选卡不再支付重复的固定稳定等待，以便缩短非动画操作时间。
2. 作为刷本用户，我希望普通卡一次识别后连续选择三张，以便避免每张卡之间重新截图和识别整手牌。
3. 作为刷本用户，我希望卡面尚未完整展开或作业要求的宝具无法确认时仍然等待，以便快速路径不会盲点。
4. 作为刷本用户，我希望三卡提交异常时有限次恢复，以便漏点不会直接丢失整场运行，也不会无限重复点击。
5. 作为刷本用户，我希望技能和攻击后主动跳过可跳过动画，以便减少可由软件消除的等待。
6. 作为刷本用户，我希望定向技能仍确认目标面板出现和关闭，以便目标选择不会被快速点击穿透。
7. 作为刷本用户，我希望遇到未知画面、意外弹窗或无法确认的动作时安全停止，以便性能优化不会牺牲运行安全。
8. 作为使用高性能通道的用户，我希望通过持续视频流读取最新画面并注入输入，以便避免每次决策都启动 ADB 截图和输入子进程。
9. 作为使用 ADB 的用户，我希望沿用相同作业和动作语义，以便高性能通道不会产生另一套战斗行为。
10. 作为使用 ADB 的用户，我希望 scrcpy 启动失败时收到明确提示并能回退，以便设备能力差异不会导致静默行为变化。
11. 作为运行中的用户，我希望视频流或控制通道中途失效时安全停止，以便旧帧和待确认动作不会跨通道错位。
12. 作为维护者，我希望两种设备通道共用动作状态机，以便缺陷修复和回放不需要维护两套战斗逻辑。
13. 作为维护者，我希望运行日志仍能计算各阶段动作间隔并记录实际通道，以便用同一口径比较优化前后结果。
14. 作为维护者，我希望高性能通道先显式启用并在验收后再默认，以便未验收实现不会改变现有用户的默认运行方式。
15. 作为维护者，我希望正常路径与异常恢复都有离线回放，以便每次行为变更都能回归验证。

## Implementation Decisions

- 战斗内动作改为动作级确认，不再让所有点击共用 0.5 秒稳定窗口；战斗外的助战、AP 和结算流程不在本次改动范围内。
- 未知画面、意外弹窗、控件或身份不确定仍禁止点击；固定延迟不能替代画面证据。
- 选卡入口必须确认五张普通卡完整展开，并且作业要求的宝具卡可确认。证据不足时继续等待，不按时盲点。
- 正常选卡复用同一手牌的识别和选择结果，以 200 ms 作为初始卡间间隔连续提交三卡。200 ms 是实机调参起点，不作为不可调整的产品承诺；若漏卡，应根据日志评估 250/300 ms，而不是恢复逐卡完整识别。
- 三卡提交后以离开选卡页或进入已识别后续画面作为确认。2 秒仍停留在选卡页时重新读取画面并最多恢复一次；仍无法确认则安全停止，不直接重复整串点击。
- 普通卡提交后不逐卡重新识别；宝具不可用等异常仍须根据新画面处理，恢复后不得复用已经失效的选择状态。
- 技能后主动点击战斗跳过区，以攻击按钮和战斗菜单恢复作为下一动作依据，不再强制要求先观察到技能动画开始。
- 定向技能仍须确认目标面板出现与关闭；技能点击后完全观察不到状态变化时，只允许一次基于新帧的恢复，否则停止。
- 第三张卡提交后每 1 秒最多点击一次战斗跳过区，直到攻击按钮恢复或出现其他已识别页面；选卡页残留时不得点击跳过区。
- 新增 scrcpy 持续视频流和输入适配，感知继续消费统一帧接口，执行器继续通过统一设备接口点击和滑动。
- ADB 与 scrcpy 共用动作状态机、作业格式和安全规则，只允许采集与输入能力及速度不同。
- scrcpy 启动失败可明确提示后回退 ADB；运行中视频流或控制中断必须在动作边界安全停止，不自动跨通道续跑。
- scrcpy 首版由用户显式选择，实机验收通过后再决定是否默认启用；任何回退都必须可见，不静默发生。
- 运行证据保留动作时间戳、动作原因、实际设备通道及足够的阶段计时，以支持同作业同设备的优化前后对比。
- 不修改作业 Schema，不把高性能通道专属字段写入作业。
- scrcpy 通道选择及其与 ADB、LDPlayer 原始帧通道的边界由独立 ADR 记录。

## Testing Decisions

- 主测试缝沿用执行器入口：假设备、截图语料和感知输入驱动真实状态机，断言外部可观察的动作、坐标、间隔、停止原因和恢复次数，不新增测试专用行为入口。
- 选卡回放覆盖正常三卡连击、卡面未展开、宝具未确认、提交后停留、一次恢复成功、恢复失败安全停止，以及恢复后不复用过期手牌。
- 技能回放覆盖无目标技能、定向技能、状态变化缺失、攻击按钮与菜单恢复、意外弹窗和动画跳过频率上限。
- 攻击回放覆盖第三张卡后的跳过、选卡页残留禁止跳过、下一面/下一回合与结算恢复。
- 两种通道必须复用同一批动作行为用例；设备适配器自测覆盖启动失败、取帧失败、输入失败和运行中断。
- 每次执行器或感知行为变更同步更新统一离线回放；每个实机故障补一条回归用例。
- 实机验收使用同一作业、同一模拟器和同区服，比较优化前后事件日志，并逐面逐回合核对作业动作没有缺失。
- scrcpy 实机验收线：普通选卡间隔中位数 ≤0.45 秒，攻击到首卡中位数 ≤1.0 秒；游戏动画本身不计入软件操作耗时。
- 200 ms 间隔必须通过实机三卡提交成功率验证；若发生漏卡，保存证据并调整参数，不以离线通过代替实机结论。
- ADB 验收关注动作一致性与安全停止，不套用 scrcpy 的速度门槛。
- scrcpy 未通过完整实机验收前不得设为默认，也不得宣称稳定。

## Out of Scope

- 助战搜索、AP 恢复、结算和连续出击流程的性能重写。
- 日服、台服执行支持。
- 新作业格式、自动配队、通用副本导航或条件分支。
- 通过关闭未知画面、弹窗、身份或目标确认来换取速度。
- 让 ADB 达到与持续帧通道相同的截图速度。
- 将 LDPlayer 原始帧通道扩展为本次唯一高性能路线。

## Further Notes

基线来自本机 `run-1795324985350-41448`、`run-1795327436357-41448`、`run-1795330615381-10172` 与 `run-1795335248071-10172` 的成功运行事件。新面事件到首次动作的基线中位数为 4.783 秒，但其中可能包含游戏过场，不把全部差值归为软件开销。

Mash 的参考实现采用 scrcpy 最新帧缓存、一次读取手牌、300 ms 固定卡间间隔和异常恢复。本项目不照搬其 300 ms 参数，而以 200 ms 起步并独立进行安全与实机验收。
