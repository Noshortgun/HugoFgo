# 05A: 画面感知适配器

## Parent

#5

## What to build

交付双速画面感知模块：同步快路径输入设备帧，输出结构化 `Observation`；后台 OCR 只按需补充字段。技术取舍见 ADR-0005，原型依据见本地分支 `prototype/perception-fast-path`。

本票只负责“看懂画面”，不推进作业、不操作设备、不实现状态机。施工顺序上优先完成 #20 的快速原始帧通道；离线规则开发可以并行。

## Observation 契约

`Perception.read(Frame) -> Observation` 至少表达：

- **基页**：`menu / support / team / battle / card / result / drops / ap_recovery / loading / unknown`。
- **画面变体**：普通/冠位助战、普通/冠位队伍等，不直接扩张执行器状态机。
- **覆盖层**：`support_confirm`、`support_party_confirm`、`repeat_dialog`、`order_change`、`command_spell_menu / target / confirm`、`class_info`、`battle_menu`、`master_skills` 等；覆盖层可与基页并存。
- **控件**：按钮、指令卡、目标位置及坐标；只有确认可用时才标记可行动。
- **可操作性**：与基页独立。`battle` 不表示攻击按钮一定可用，`card` 不表示仍能继续选卡；`unknown / loading / 转场` 永远不输出危险动作。
- **字段状态**：区分 `not_applicable / not_read / pending / uncertain / confirmed`，不能用一个全局 `uncertain` 混淆“不需要读”和“读取失败”。

第三张指令卡提交后游戏立即开始攻击，不存在额外的攻击确认状态。即使截图仍属战斗基页，也不得继续输出选卡动作。

## 同步快路径

- 禁止 OCR、网络和按次付费服务；使用区域化模板、颜色、边缘、布局关系与“必须出现 / 必须不出现”判据。
- 不采用全局图像最近邻作为正式方案；原型跨会话仅 42.9%。多证据原型为 44/49，仍需正式独立验收。
- 相同帧可以 hash 缓存；新帧识别需要记录耗时分布。最终端到端速度门槛在 #12 与 BBChannel 同场验收，本票不另造脱离设备通道的秒级指标。
- 执行器动作前的连续稳定确认属于 #17；本票必须提供足够的逐帧证据与可操作性，不能在识别器内擅自推进作业。

## 后台 OCR

- 只补充 NP、从者属性、面/回合数值、AP 数值等当前需要的字段；普通纯作业流程不为未使用字段付出同步 OCR 成本。
- 请求和结果绑定 `frame hash + request ID`；返回时画面已变化则结果只能进入缓存，不得驱动当前动作。
- 后台线程不修改已经交付的旧 Observation；新结果以新快照或事件交付。
- 仅当前动作必须依赖字段且当前帧结果未完成时才阻断；空闲预取不得阻塞同步快路径。

## 验证素材口径

当前 `.scratch/annotated/index.json` 是 **28 屏、19 个待审核状态标签**，不是“25 类已完成验收”。这些素材全部作为开发与回归集，不能证明独立泛化。

算法、模板、阈值和判据冻结后，再采集未参与调参的真实截图作为留出集；由用户按清单操作模拟器，脚本负责截图与断言。menu、转场、覆盖层混淆和关键字段必须补足样本。

## Acceptance criteria

- [ ] 同步 `read()` 全程不调用 OCR，输出基页、变体、覆盖层、控件、可操作性和字段状态。
- [ ] 基页与覆盖层不再互斥；结算页残留战斗元素、御主技能覆盖战斗、技能目标与令咒目标相似等情况有专门用例。
- [ ] 第三张卡提交后的真实帧输出不可继续选卡；loading、转场和未知帧没有危险可行动控件。
- [ ] 字段按上述五种状态表达；后台 OCR 不阻塞普通快路径，旧帧结果会被拒绝。
- [ ] 28 屏开发/回归集全部有明确断言；关键误判有用例，不能用同源截图成绩代替留出验收。
- [ ] 留出集在判据冻结后采集并通过；未通过前不得宣称完整 #16 或稳定。
- [ ] 国服识别配置集中管理，不包含日服/台服规则。
- [ ] 不直接调用 adb、不读取作业、不实现状态机；既有 `npm run replay` 与构建保持通过。

## Prototype evidence

本地分支 `prototype/perception-fast-path` 保留可运行脚本与结果。已测：多锚点原始帧约 6 ms；后台 OCR 时快路径 P95 16.5 ms；LDPlayer 快速通道见 #20；最小实机闭环到达选卡页后停止，未点击指令卡。原型不是正式实现。
