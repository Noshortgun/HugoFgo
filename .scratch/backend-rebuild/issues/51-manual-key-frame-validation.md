# 51: 人工关键帧规则回放与作业契约修复

Blocked by: #49

## What to build

以 2026-11-23 手动执行 `娄希、娄希、奥伯龙` 作业时确认的 29 张关键帧建立可重复的规则回放。每帧记录必要上下文、人工确认的画面字段与下一动作；测试验证任意手牌上的规则，不把一次抽卡结果当作固定答案。

先将已发现分歧变成会失败的自动测试，再修复助战搜索、队伍核对、字段读取和逐张选卡契约。本票只证明离线规则与已采集实机画面，不把回放通过写成实机稳定。

## Acceptance criteria

- [ ] 29 张人工关键帧及来源索引进入正式素材与回放，正常路径可以按上下文串联到单场完成；缺失身份、字段或动作时测试明确失败。
- [ ] 助战已处于目标职阶时不得重复点击职阶；当前列表未翻到底时先向下翻找，翻到底仍无目标才允许列表更新。
- [ ] 队伍确认页核对作业要求的从者、助战概念礼装与御主礼装；任一项不确定或不符时不得开始任务。
- [ ] 普通指令卡按卡序位置逐张选择：从者、卡色、暴击率依次比较，完全并列才选最左；宝具不参与普通卡排序，固定宝具位置只占用对应卡序。
- [ ] 指令卡暴击率读取进入真实帧断言；第二面卡1（10%）与卡4（30%）必须先选卡4，宝具固定第二位不改变普通卡规则。
- [ ] 第一面己方娄希3技能后的画面应确认第1面、第1回合及 NP 40/100/40；字段读取失败不得被回放报告掩盖。
- [ ] 作业御主礼装改为新春装束 `atlas-260`，第三面依次使用技能1（己方全体）与技能2（己方娄希）。
- [ ] `npm run replay` 与执行器测试覆盖上述行为；每个原失败用例在修复前红、修复后绿。
- [ ] 文档区分人工关键帧规则回放、旧故障回归和实机验收；未经新采画面与完整实机复验不得宣称稳定。

## Out of scope

- 不在本票完成 scrcpy 性能验收或默认启用。
- 不扩展其他区服、副本或全部从者的泛化承诺。
- 不用固定手牌答案替代任意手牌上的规则测试。
