# 63: 为运行证据生成中文动作摘要

Source: 2026-11-24 用户反馈运行记录难以阅读；参考 `run-1795498348917-18264`。原始事件中的 Unix 时间、控件名和确认阶段必须反复对照代码与作业才能理解。

## What to build

每次运行在证据目录生成按场、面、回合和动作组织的中文摘要，并为既有运行提供重新生成入口。原始事件继续保留给程序审计，摘要使用作业中的从者与动作名称，明确区分已点击、画面确认和没有独立生效确认，不把输入记录写成技能或动作已在游戏内生效。

## Acceptance criteria

- [ ] 每次运行生成中文动作摘要，原始 `events.jsonl` 的内容和审计用途不变。
- [ ] 摘要按第几场、第几面、第几回合和动作顺序组织，使用作业中的从者与动作名称，不只显示槽位控件名。
- [ ] 时间使用可读时间或相对耗时，不要求读者换算 Unix 时间戳。
- [ ] 每个动作明确区分已点击、画面已确认、没有独立生效确认；不得把点击或画面确认表述为游戏效果已确认。
- [ ] 结尾汇总运行状态、停止原因、完成场数和未执行的计划动作。
- [ ] 可为 `run-1795498348917-18264` 重新生成摘要，准确显示希耶尔 3 技能已点击且没有独立生效确认，不得写成漏点或已成功发动。
- [ ] 摘要覆盖正常完成、手动停止和失败停止，事件缺失或证据不完整时明确标注，不猜测结果。
- [ ] 当前能力与测试文档同步更新，桌面历史界面复用不在本票范围。
- [ ] `npm run replay` 与 `npm run verify` 全绿。

## Blocked by

None (can start immediately)

## Out of scope

- 不改变原始事件 Schema 或机器审计规则。
- 不改造桌面历史界面。
- 不新增技能效果、冷却或 NP 状态识别。
- 不用摘要把输入日志推断为游戏实际效果。
